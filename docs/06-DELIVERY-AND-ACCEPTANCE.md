# 一期交付与验收基线

状态：**已确认，受 `00-V1-BASELINE.md` 约束**

目标：把产品范围转成可分阶段实现、可验证、可停止的交付计划

## 1. 交付原则

- 一期按纵向闭环推进，每个里程碑都应产生可以运行和验证的结果。
- 后一个里程碑不能用“先搭框架”为理由反向扩大前一个里程碑。
- 原始记录、搜索和恢复优先于 AI；没有 Provider 时核心产品仍完整可用。
- 测试验证契约和真实风险，不追求无意义覆盖率数字。
- 默认测试不能调用付费模型、真实服务器、SSH、外部 Notion 或企业微信。
- 所有测试数据必须是合成或脱敏数据；真实密码、Token、私钥、内部地址和用户笔记不得进入仓库或 CI 日志。
- 一个里程碑的退出条件未满足时，不把它标为完成，也不以截图替代行为验证。
- 本文不承诺日期。排期由可用时间和实测复杂度决定，不让虚构工期驱动删减安全或数据边界。

## 2. 交付物定义

一期最终交付物仅包括：

1. Vue 3 + TypeScript Web 应用。
2. Go 模块化单体 API。
3. Node.js + TypeScript AI worker。
4. PostgreSQL 迁移与检索实现。
5. Docker Compose、Caddy、初始化、备份和恢复脚本。
6. JSON Schema、API 契约、脱敏 fixtures、自动化测试和必要运维文档。

不交付浏览器扩展、Tauri/Electron、Notion/企业微信通用导入器、OCR 服务、语义搜索、插件系统或服务器执行能力。

## 4. M0：工程骨架与契约

### 4.1 范围

- 创建 `apps/api`、`apps/web`、`apps/ai-worker`、`deploy` 和 `tests` 的真实最小目录。
- 固定 Go、Node、pnpm、PostgreSQL、Caddy 的具体版本，并提交 lockfile；V1 内只做必要升级。
- 建立本地 Docker Compose：Caddy/gateway、API、worker、PostgreSQL 四个服务，不增加其他常驻服务。
- API 提供结构化错误、请求 ID、`/health/live` 和 `/health/ready`。
- 建立顺序数据库迁移、开发数据清理和测试数据库入口。
- 把 `ai-artifact.schema.json` 接入 API 与 worker 的同一契约测试。
- Web 建立深浅主题令牌、应用壳、基础路由和最少可访问组件，不提前实现所有页面。
- 根 Makefile 只包装开发、检查、测试、构建、启动、停止和迁移等真实命令。
- 提供 `env.example`，不包含可用生产凭据。

### 4.2 依赖锁定门禁

实现类别已经由 `01-ARCHITECTURE.md` 第 12 节冻结。M0 只负责：

- 选择兼容的稳定补丁版本并写入 `go.mod`/`pnpm-lock.yaml`。
- 检查实际包名、许可证、Node/Go/PostgreSQL 支持范围与 Pi 三协议能力。
- 把确切版本写入构建文件，不在文档里维护另一份易漂移版本表。
- 如果某个冻结库有具体不兼容或停止维护证据，先报告和更新基线；不得私自并装替代框架做比较。

不得自制已有成熟库能可靠解决的密码学、TOTP、数据库迁移、可访问弹层或 JSON Schema 实现。

### 4.3 明确不做

- 不建通用 DDD 框架、事件总线、依赖注入容器、代码生成平台或内部 SDK。
- 不创建没有消费者的未来工具模块、插件接口或抽象存储适配器。
- 不接真实 Provider，不实现业务页面假数据大屏。
- 不创建 Kubernetes、CI 发布流水线矩阵或多环境配置中心。

## 5. M1：身份与原始事实层

### 5.1 范围

1. 数据库约束和迁移先表达“单所有者”和“原始不可普通更新”。

3. API 完成纯文本创建/读取事务。
4. Web 完成登录、TOTP 与快速记录。
5. Web 完成原始详情和最小列表。
6. 最后补齐可信设备管理、恢复码和所有错误状态。

### 5.3 退出条件

- [x] 密码哈希、TOTP 加密、恢复码哈希和 Cookie 属性符合安全基线。
- [x] 无可信设备时密码后要求 TOTP；可信 90 天只跳过 TOTP，不跳过密码。
- [x] 同一未过期 enroll challenge 重复请求 TOTP setup 返回同一个 pending secret，不静默轮换导致已扫码设备失效。

## 7. M3：外部 Agent 与 Provider

### 7.1 范围

覆盖 `PROVIDER-01..03`、`EXT-01..03`：

- Provider 创建、编辑、删除/停用、密钥替换和连接测试。
- 手工模型目录与默认模型选择。
- `OpenAI Chat Completions`、`OpenAI Responses`、`Anthropic Messages` 三个协议适配。
- 自定义 Base URL，但不支持执行自定义 Provider 代码。
- PAT 创建、一次显示、scope、到期、撤销和最后使用时间。
- 外部 Agent 读取授权记录、创建新原始记录、提交候选 artifact 和发起任务。
- 服务端对外部 artifact 执行 Schema、引用、归属、敏感与业务校验。

### 7.2 协议测试矩阵

每种 Provider 协议至少包含本地 mock fixture：

| 情况 | 预期 |
|---|---|
| 正常文本响应 | 解析为统一模型结果 |
| 正常工具调用 | 只接受当前任务白名单工具 |
| 401/403 | 标记凭据错误，不重试、不泄露响应 |
| 网络中断/超时、408、429、500/502/503/504 | 同一 task 内按策略最多重试 2 次，且不突破任务 deadline |
| 其他 4xx/5xx、Schema 错误、能力不匹配 | 不自动重试，返回稳定协议错误 |
| 畸形 JSON/缺字段 | 稳定协议错误，不保存 artifact |
| 超长输出 | 在模型限制和服务端限制处终止 |
| 不支持图片 | `analyze_image` 在调用前拒绝 |

默认只需要非流式 Provider 调用。AI 任务本来是异步的，一期不为了打字机效果增加流式协议和 SSE 解析复杂度。

### 7.3 退出条件

- [ ] API Key 创建后不可读取明文，数据库 dump 中是带版本的密文。
- [ ] 连接测试错误不会在日志、响应或 UI 暴露 Key/完整上游响应。
- [ ] 三协议用 mock 完成正常、鉴权、限流、超时和畸形响应测试。
- [ ] Provider 连接测试只接受属于当前 Provider 的内部 `modelId`，API 只调用一次 worker 的单用途内部 RPC，worker 复用真实 adapter 和固定最小预算发出一次上游请求；无 usage 时返回 `null`，API 不直连 Provider，失败不回显上游正文。
- [ ] 连接测试上游 401/403 映射为 `AI_PROVIDER_CREDENTIALS_INVALID`，网络错误、408、429、5xx 和畸形响应映射为 `AI_PROVIDER_UNAVAILABLE`，两者都不自动重试。
- [ ] 自定义 Base URL 表示协议根地址，adapter 只规范化末尾 `/` 并拼接固定 endpoint；带/不带末尾 `/`、自定义路径前缀均通过，userinfo/query/fragment 和重定向被拒绝，HTTP 仅按明确开发/内网规则开放。
- [ ] Provider 只对网络中断/超时、408、429、500/502/503/504 有界重试；401/403、其他 4xx/5xx、Schema 错误与能力不匹配零重试。
- [ ] PAT 明文只展示一次，撤销后立即无效；每个外部 Agent 端点按契约 scope 矩阵验证缺失、越权和允许路径，返回稳定错误。
- [ ] `sensitive:read` 只作为读取 scope 的附加门槛，单独持有时不赋予记录或附件读取能力。
- [ ] 未授予 `sensitive:read` 的 PAT 只能看到遮挡元数据，无法读取敏感原文/附件或提交敏感 artifact。
- [ ] `records:write` 只能新建条目或向已有条目追加新的 supplement，不能更新已有原文或给旧 raw record 追加附件。
- [ ] 相同 sourceType + namespaced externalId 重跑迁移时返回已有记录，不重复创建也不覆盖。
- [ ] 外部 artifact 在 Schema 或 source reference 错误时不进入候选列表。
- [ ] 外部 Agent 不经过 AI worker 也能完成一次性迁移所需的新增原文与提交派生结果。

## 8. M4：内置 AI 任务引擎

### 8.1 范围

覆盖 `AI-01..05` 和动态 AI blocks：

- Node/TS worker 的模型层、受控 Agent loop、领域任务层。
- `organize_record`、`review_record`、`analyze_image`、`batch_organize`。
- 手动、批量、每日/每周调度，默认关闭。
- PostgreSQL 任务 claim、租约、心跳、取消、失败和有限重试。
- `block`、`redact`、`allow` 三种敏感策略。
- 候选 artifact、版本历史、激活、重新生成和来源定位。
- 前端对所有 v1 block 类型的固定组件渲染。
- 模型审阅 warning 与原始片段引用。

### 8.2 Agent loop 硬限制

默认单任务限制：

- 最多 4 轮模型交互。
- 最多 8 次领域工具调用。
- 最多读取 10 条相关记录。
- 最长运行 5 分钟。
- 取消信号在下一次 Provider/工具边界生效。

允许工具只有：读取当前记录上下文、读取已授权附件、搜索相关记录、提交候选 artifact。不得增加 Shell、SSH、SQL、浏览器、任意 HTTP、任意文件系统、代码执行或写原始记录工具。

### 8.3 任务测试矩阵

每种任务至少验证：

- 正常完成并生成 Schema 合法 artifact。
- 同一 item + task type 同时最多一个 queued/running task；不同类型仍可并行，batch 遇到重复分支只记录明确 skip reason。
- 两个 worker 并发 claim 时只有一个成功，过期 lease 的旧 worker 不能提交结果。
- Provider 未配置、模型被删除、上下文超限、超时、取消。
- 上下文不足时不发送静默截断内容，也不自动启动递归总结。
- 模型请求未知工具、重复工具、超出次数、返回非 JSON。
- source fragment/attachment 不属于任务记录。
- 模型返回错误 artifact type、文本结果无来源片段、图片结果漏掉已发送图片。
- API 拒绝重复 block ID、子结构引用不在顶层来源集、表格行列不等和忽略大小写后重复标签；Go 与 worker 对合法/非法 UUID fixture 结论一致。
- `block` 对敏感/未知记录零外部请求。
- `redact` 外发内容是占位副本，原文和 artifact 不被占位映射覆盖。
- 敏感/未知图片在 `redact` 下零外发并返回可解释状态。
- `allow` 只有设置明确开启后可外发。
- worker 在提交成功后崩溃，任务不会创建两个相同的活动版本。
- queued 取消返回 cancelled，running 取消返回 `202` 且保持 running 并标明 `cancelRequested=true`，重复取消 cancelled 幂等成功，取消 succeeded/failed 固定返回 `AI_TASK_NOT_CANCELLABLE`。
- complete 先查 `task_run_id` 已有 artifact；成功后的同 lease 重试返回原 artifact/终态，只有不存在 artifact 时才要求 running、有效 lease 且无取消请求。
- 取消先于首次 complete 事务提交时不创建 artifact；并发 complete 由 `task_run_id` 唯一约束收敛为同一个版本。
- worker 租约过期只在无取消请求时自动重新领取一次；已有取消请求的失联任务直接 cancelled。用户重试产生新任务并保留旧失败历史。
- Provider 网络重试留在同一个 task run 内；用户点击“重试”创建带 `retry_of_task_id` 的新任务，不把旧失败任务改回 queued。
- batch 六种稳定 skip reason 与输入条件逐一匹配，child 状态计数与 created children 一致，skip 总数等于固定 `byReason` 之和；所有分支都有稳定 skip reason 时，以 succeeded 和全 skipped 摘要结束。
- batch 子任务全部终止后按“父任务取消 > 任一 child failed > 任一 child cancelled > succeeded”聚合；取消 running 父任务传播到 queued/running 子任务，已经成功的子任务与 Artifact 保留。
- 新增 raw record/ready 图片后 active artifact 返回计算值 `isStale=true` 且继续参与搜索；所有旧版本仍可查看，未作废版本可主动激活，已作废版本只能查看，未激活历史版本不进入普通搜索。
- 已作废 Artifact 的激活和应用建议请求均被拒绝；作废当前版本时不自动回退到旧版本。
- worker 离线时，录入、搜索、浏览和下载不受影响。

### 8.4 正确性文案验收

- [ ] UI 状态使用“模型审阅完成”，不存在“验证通过”“安全可执行”。
- [ ] 每个 AI 命令显示“模型整理，执行前请核对原文”。
- [ ] warning 区分“根据原始片段”和“根据模型知识”，无法确认时写“不确定”。
- [ ] 用户可从 warning/AI block 定位原始来源。
- [ ] 激活 artifact 只改变派生视图，不覆盖原文、人工标题、目录或正式标签。
- [ ] 重新生成创建新版本；旧版本和生成信息可查看。
- [ ] stale artifact 激活或应用建议前提示其未覆盖最新原始记录，但不自动删除、停用或从搜索移除。

### 8.5 退出条件

- [ ] 四种任务完成正常、失败、取消和重试闭环。
- [ ] 有界 loop 在所有异常 fixture 下都能停止，不无限调用模型。
- [ ] 三种敏感策略有网络层 spy 证明实际外发内容符合设置。
- [ ] API 和前端都拒绝模型生成的 HTML、脚本、未知组件和越权引用。
- [ ] 定期任务默认关闭，只处理当前 artifact 未覆盖最新 raw records/ready 图片集合或明确重建的条目，不重复轰炸 Provider。
- [ ] 日/周调度按配置时区执行，同一时间窗只创建一次且最多 20 条；API 重启不会重复批次。
- [ ] 批量任务逐条隔离，一条失败不篡改其他条目。
- [ ] 手动批量去重且最多 100 条，父任务只汇总、子任务各自生成版本。
- [ ] 批量任务分别处理正文和图片；混合条目可以同时生成整理与图片分析，纯文件跳过；未配置视觉模型时不误用文本模型，也不阻塞正文整理。
- [ ] 动态 block 在深浅主题、长内容和未知新版 block 下可用。
- [ ] 默认自动测试没有产生真实模型费用。

## 9. M5：部署、恢复与发布验收

### 9.1 范围

- 生产 Compose、Caddy HTTPS、Secret、数据卷和日志轮转。
- 初始化、备份、恢复、升级和完整性检查脚本。
- 性能数据集和目标主机实测。
- 浏览器、响应式、深浅主题、键盘和可访问性检查。
- 安全基线清单、依赖漏洞与许可证检查。
- 用户文档：首次部署、更新、备份、恢复、Provider 配置和限制。

### 9.2 发布环境验收

- [ ] 使用实际生产形态而非开发服务器构建并启动。
- [ ] 正式域名 HTTPS 有效，HTTP 跳转；仅 80/443 暴露。
- [ ] 容器重启后会话、记录、附件、索引和任务状态符合预期。
- [ ] AI worker/Provider 故障不会影响核心功能。
- [ ] 主机磁盘只读/空间不足、数据库不可用和附件目录无权限时失败可解释且不产生半记录。
- [ ] 日志轮转启用，错误场景日志没有正文、Cookie、Authorization 或 Key。

### 9.3 性能验收

固定合成数据集：50,000 条原始记录、500,000 个搜索片段、附件总量 20 GiB；附件实际字节可使用可重复生成的非敏感稀疏/样本文件，报告时说明方式。

在最终部署硬件上记录：

- 关键词搜索第一页服务端 P50/P95，P95 目标 ≤ 500 ms。
- 纯文本保存服务端 P50/P95，P95 目标 ≤ 300 ms。
- 固定视图第一页、记录详情和附件元数据查询。
- 索引重建总耗时和数据库峰值空间，仅作容量记录，不设伪精确 SLA。
- Web 首屏构建体积、桌面首次可交互和长列表滚动问题；基于实测优化，不预装复杂性能框架。

性能测试必须记录 CPU、内存、磁盘类型、PostgreSQL 版本和数据生成方式。未达标先用查询计划和 profile 找实际瓶颈，不能直接引入搜索集群、缓存或消息队列。

### 9.4 恢复验收

- [ ] 生产形态完成一次静默备份，snapshot 含数据库 dump、原始附件和配置清单。
- [ ] 在空目录/空数据库恢复，不复用原容器数据卷。
- [ ] 随机抽查至少 20 条文本、5 张原图、5 个普通附件及其字节一致性。
- [ ] 恢复前逐一验证所有数据库引用附件的存在性、大小和 SHA-256；任一不一致时恢复验收失败且 Caddy 不启动，现场保留供改用已验证 snapshot 或排查。checksum 不承担去重、内容寻址或存储路径职责。
- [ ] 登录密码、TOTP、可信设备撤销状态、目录、标签、回收站和 AI 版本恢复正确。
- [ ] 完整性检查能报告缺失附件和孤儿附件，且默认不删除。
- [ ] 恢复记录包含 snapshot ID、环境、耗时、失败点和修正，不含敏感正文。

### 9.5 UX 与兼容验收

- [ ] 当前桌面 Chrome、Edge、Safari 完成核心 E2E；Firefox 完成基本兼容检查。
- [ ] 1366×768、1440×900、1920×1080、1024×768、390×844 覆盖关键页面。
- [ ] 深色/浅色、200% 缩放、键盘-only、reduced motion 和基础屏幕阅读器检查完成。
- [ ] 登录、录入、搜索、详情、附件、任务、设置都有加载/空/错误/溢出状态。
- [ ] 原始/AI 边界、敏感遮挡、逐块复制和危险确认符合 UX 基线。
- [ ] 搜索与快速记录都有可见入口；快速记录在 M1、搜索在 M2 smoke 后回填的具体快捷键，在 Chrome、Edge、Safari 不触发地址栏、无痕/InPrivate 窗口或其他浏览器常用行为。

## 11. 测试层次与停止规则

### 11.1 Go API

- 纯函数/规则使用 `go test` 单元测试：排序权重、敏感策略、状态机、文件名净化。
- 数据约束、事务、搜索和任务 claim 使用真实 PostgreSQL 集成测试，不用内存数据库模拟 PostgreSQL 行为。
- HTTP handler 测试覆盖状态码、稳定错误码、认证、scope、CSRF、分页和幂等。
- 迁移测试从空库向前应用；涉及兼容变更时从上一个发布 Schema 副本升级。

### 11.2 Web

- 组件测试只覆盖有状态交互和边界，不为纯样式生成大量脆弱快照。
- 浏览器 E2E 覆盖登录、录入、搜索、复制、附件、AI 候选和设置主路径。
- 视觉回归只选择应用壳、搜索/详情、快速记录、登录和设置等关键页面的固定视口；差异需要人工判断，不能自动更新基线掩盖问题。
- 可访问性自动扫描是辅助，仍需键盘、焦点、缩放和屏幕阅读器人工抽查。

### 11.3 AI worker

- Provider adapter 使用本地 mock HTTP，固定请求/响应 fixture。
- Agent loop 使用确定性假模型测试工具白名单、次数、取消、超时和事件序列。
- artifact 同时通过 worker 预校验和 API 最终校验。
- 真模型烟测是发布前可选手工检查，需要用户明确启用并确认费用；结果不作为唯一验收证据。

### 11.4 何时不运行全量测试

- 只改文档：运行链接、Schema/格式和术语一致性检查。
- 只改单组件样式：运行对应组件和关键视口，不启动数据库全量集成。
- 只改单 Provider adapter：运行该协议 fixture 和共享 artifact 契约。
- 改数据库 Schema、公共 API、artifact Schema、认证或敏感策略：运行所有直接生产者/消费者与迁移路径。
- 完成里程碑或发布候选：运行该里程碑完整门禁；M5 运行全套。

输入未变化时不重复运行相同检查。测试失败先修复直接原因，再只重跑受影响检查；不要用重试掩盖非确定性。

## 13. 缺陷分级与发布停止条件

### P0：立即停止发布

- 原始记录或原始附件被普通编辑/AI 覆盖、丢失或关联错位。
- 未认证可访问数据，或敏感内容/Secret 出现在日志、URL、静态产物。
- AI 获得命令执行、任意网络/文件系统能力，或绕过敏感策略外发。
- 备份无法恢复，迁移破坏原始数据。

### P1：修复后才能发布

- 登录/MFA/可信设备/CSRF 可绕过。
- 搜索主要路径不可用或结果稳定性错误。
- 附件边界、路径或活动内容处理错误。
- UI 把模型审阅表示为已验证，或无法查看来源原文。
- 核心浏览器、深浅主题、键盘或 200% 缩放阻断主流程。

### P2：可以记录后评估

- 不阻断任务的局部对齐、辅助文案或低频状态问题。
- 不影响正确性的性能优化机会。
- 明确属于 `BACKLOG.md` 的二期增强。

P2 不能被用来降级真实数据、安全或可访问性阻断问题。

## 14. 一期 Definition of Done

只有以下全部成立，一期才算完成：

- 所有需求在覆盖矩阵有实现和证据，P0/P1 为零。
- 无 Provider、worker 停止和外网模型不可用时，登录、录入、搜索、浏览、复制、附件与备份仍工作。
- 原始事实层、人工元数据和版本化 AI 派生层在数据库、API 与 UI 三处边界一致。
- 三 Provider 协议和外部 Agent API 通过本地契约测试。
- 受控 AI loop 在异常输入下有界停止，没有高权限通用工具。
- Docker 公网边界、Secret、日志、备份和空机恢复通过。
- 性能目标在实际部署硬件记录并满足，或用户基于真实数据明确接受偏差。
- UX 发布门禁通过，页面没有不可达的假入口或延期功能占位。
- README 和运维文档能让未来的自己从零部署、升级、备份和恢复。

完成后立即停止一期开发。后续能力从 `BACKLOG.md` 单独选择、重新定界，不把二期悄悄塞进一期收尾。
