# 已确认版本之外的候选清单

## 1. 这份文档是什么

本文件只记录已经讨论过、但没有进入当前权威基线的方向，防止实现 Agent 把“以后可能需要”误解成当前范围。

- Backlog 条目不是承诺、排期、隐藏验收项或预留接口的理由。
- 当前代码不得为这里的条目创建空页面、数据库表、feature flag、插件点或未使用抽象。
- 选择某条进入下一期时，先补用户任务、成功标准、数据与安全边界，再更新总基线。
- 没有真实使用证据时，优先保持现有简单实现。

## 2. 已从 Backlog 提升的能力

以下能力已经用户确认并进入 `docs/09-V2-TOOLBOX-BASELINE.md`，不再是 Backlog：

- V2.0：Base64、JSON、URL、JWT、时间/Cron、哈希摘要与校验和、正则、YAML。
- V2.1：阿里云机器翻译和应用级免费额度硬停止。
- V2.2：浏览器 Tesseract.js 单图 OCR、用户确认的阿里云 OCR 和 OCR 后翻译。

它们均已实现并包含在 `v2.2.0-rc.1` 发布候选中；真实云服务与稳定版门禁状态以 `docs/13` 为准。后续实现范围只以新的权威基线为准，不从本文件推导。

## 3. 进入实现前的判断门槛

候选能力只有同时回答下列问题才可进入新一期：

1. 它解决的具体高频工作是什么？
2. 当前一期能力为什么无法完成，手工替代的成本有多高？
3. 哪些数据会被读取、写入、上传或执行？
4. 是否增加常驻进程、模型、数据库、密钥或公网边界？
5. 最小可交付闭环是什么，哪些相邻功能仍然不做？
6. 如何备份、迁移、撤销或从失败中恢复？

只有“看起来以后有用”不构成实现理由。

## 4. 已讨论的近端候选

### B-CLIENT-01 浏览器扩展

用户场景：在 Windows 或临时电脑上，把当前选中文本/网页片段快速发送到开发百宝箱，减少打开页面的步骤。

进入条件：

- Web 快速录入 API 已稳定。
- 能明确扩展要读取的页面权限，并接受浏览器商店/签名维护成本。
- 先做最小“发送选中文本/当前 URL”，不做密码自动填充或全网页抓取。

一期处理：公共 API 已保留 `browser_extension` 来源枚举，但不提供扩展代码或 UI。

### B-CLIENT-02 Tauri 桌面壳

用户场景：macOS 为主、Windows 为辅，希望有常驻入口、全局快捷键和更自然的剪贴板体验。

进入条件：

- Web UI、路由和认证在浏览器中稳定。
- 明确原生能力清单，例如全局快捷键、托盘、开机启动；仅“把网页套壳”不足以证明价值。
- 完成自动更新、签名、公证与本地 Secret 存储方案评估。

实现边界：优先复用同一 Vue 应用；不为桌面壳复制一套业务 UI。没有原生能力需求时继续使用浏览器。

### B-MIGRATE-01 Notion 一次性迁移工具

当前决定：一期产品不内置 Notion 导入。用户可以在系统上线后，让 Codex/一次性脚本通过 PAT 把现有 Notion 内容迁移成原始记录和附件。

候选工具需要：

- 保留页面层级、原始 block 文本、图片原件、外部 ID、外部路径和原始时间可信度。
- 导入幂等，不把 AI 整理结果冒充原文。
- 对 Notion 数据库、页面、代码块、图片和普通附件使用合成 fixture 验证。
- 真实迁移前生成预览与数量报告，但不把真实内容写入仓库。

只有迁移需要重复执行或用户希望自助操作时，才考虑产品内导入 UI。

### B-MIGRATE-02 企业微信历史迁移

当前资料主要是用户发送给自己的消息。候选方案按可获得的数据源选择：官方导出、用户提供的文件或受控复制；不得抓取本地数据库、绕过客户端权限或承诺聊天记录一定可取。

最小目标是：按消息保存原始文本/图片/文件、消息时间和来源标识，重复导入不重复创建。企业微信平台限制需要实施时重新调研。

### B-SEARCH-01 真正的语义搜索

一期没有 embedding 模型，因此只提供 PostgreSQL 关键词、子串、trigram 和结构化过滤，不能称为语义搜索。

未来候选：

- 用户配置外部 embedding API；或
- 用户明确接受本地小型 embedding 模型的下载、内存/CPU 与运维成本。

进入条件：

- 用用户脱敏查询集证明关键词搜索确实漏掉重要结果。
- 选定可持续的中文、英文、命令混合 embedding 模型。
- 定义模型版本变化后的重建、成本、敏感内容策略和无模型降级。
- 只有届时才评估 PostgreSQL `pgvector`；不预先建向量字段或索引。

一期可以保存 AI 生成的标题/关键词并纳入普通检索，但不得把它包装成向量语义搜索。

`B-IMAGE-01` 已提升为 V2.2；历史上“本地 OCR 容器”的候选方向已被明确拒绝，V2.2 只在浏览器按需运行 Tesseract.js。

## 5. AI 与检索增强候选

### B-AI-01 联网资料核对

可能价值：对过时命令、软件版本和官方文档变化给出带来源的建议。

高风险边界：这仍不能证明命令适合用户的目标服务器。进入实现前必须限定可访问域名、引用与时间、敏感查询外发方式和成本；不能给 Agent 任意浏览器/HTTP 工具，也不能把结果标成“已验证”。

### B-AI-02 搜索重排与问答

只有普通检索已经召回候选但排序明显不足时，才评估模型 rerank。RAG 问答、跨记录总结和对话历史是独立产品闭环，不通过在搜索框里顺手加聊天入口实现。

### B-AI-03 更多任务类型

任何新任务都需要独立 Schema、工具白名单、输入上限、输出语义和 UI。候选例子可以来自真实使用，如合并重复笔记或生成检查清单；没有高频样本前不实现通用工作流编辑器。

### B-AI-04 本地模型

用户当前部署没有稳定本地推理能力。只有明确选择硬件、模型、更新方式和性能目标后，才评估本地 LLM/视觉/embedding。不得让一期容器默认下载数 GB 模型或探测 GPU。

## 6. 存储与运维增强候选

### B-STORAGE-01 S3/对象存储

触发条件：附件需要跨主机共享、单机磁盘不够、或用户已有可靠对象存储并希望直接备份。届时在真实第二个实现出现后抽取 BlobStore 接口；一期不为它预建 MinIO。

### B-OPS-01 在线备份与时间点恢复

一期接受个人应用的短暂停写备份窗口。只有该窗口实测不可接受，或 RPO 需要显著短于一天时，才评估 WAL 归档、PITR、文件系统 snapshot 或对象存储版本化。不要直接上高可用 PostgreSQL。

### B-OPS-02 专用监控

只有结构化日志和状态页无法定位反复发生的问题时，才评估 Prometheus/Grafana/Loki。先列出需要回答的具体问题和指标消费者，不为“标准架构图”增加三套服务。

### B-OPS-03 在线主密钥轮换

一期只有一个活动应用主密钥版本，离线恢复材料是核心。只有真实轮换需求出现后，再实现双版本解密、重新加密命令和失败恢复；不建设 Vault/KMS 集群。

### B-ATTACH-01 文件正文解析与预览

PDF、Office、压缩包和配置文件正文检索各自有格式、安全与资源成本。需要时按一种具体格式做独立闭环，不引入“万能文档解析流水线”。

## 7. V2 之后的未来小工具

开发百宝箱已确认 V2 的十个工具。它们之外的下一个工具仍必须由真实重复任务驱动，不为证明架构可扩展而增加。

新增工具的默认方式：

1. Web 增加 `modules/<具体工具>` 路由和导航项。
2. 需要后端时在 Go 单体增加 `internal/<具体工具>`。
3. 只复用已有身份、设置和附件能力。
4. 数据模型与 API 归该具体模块，不塞入 `knowledge` 的万能表。
5. 有两个真实消费者后再抽共享组件。

不会因为“以后很多工具”而预建：

- 动态插件 manifest 或市场。
- 用户上传 JavaScript/脚本。
- 每工具独立微服务、数据库或消息主题。
- 通用低代码表单、工作流、任务编排器。
- 空的“工具中心”页面。

当用户确定 V2 之后的新工具时，在本节新增具体条目、用户任务和边界，再决定是否进入开发。

## 8. 不是普通 Backlog 的产品方向变化

以下能力与当前产品模型根本冲突，不能由实现 Agent 当作自然演进直接加入：

### 多用户、分享、组织与 RBAC

会改变几乎所有表的所有权、PAT、安全、搜索、备份和 UI。只有用户明确把产品从个人实例改成协作产品时，才重新立项；一期不预埋 `tenant_id`。

### 端到端加密/零知识

会与服务端明文搜索、AI 分析和易恢复目标冲突。若未来选择，必须明确哪些能力放弃或移到客户端，并设计密钥恢复；不能只在现有字段外包一层加密。

### 密码管理器

开发百宝箱允许保存混在命令中的密码、Token、私钥和内网地址，但不是密码保险库。密码生成、自动填充、Secret 轮换、剪贴板自动清除和浏览器凭据注入属于另一个安全产品。

### Shell/SSH/SQL/部署执行

当前 AI 只整理和建议。若未来要执行服务器操作，必须作为独立高风险产品重新设计目标授权、审批、审计、超时、回滚和凭据隔离；绝不能给现有 AI worker 增加一个通用执行工具。

### 第三方插件与脚本生态

会引入代码执行、签名、权限、升级和供应链边界。未来简单工具继续使用编译期模块，除非存在明确的第三方开发者和安装需求。

## 9. 明确拒绝的伪需求

除非用户重新提出并给出具体场景，不因为 Agent 建议加入：

- “企业级”租户、审批、审计大屏。
- Kubernetes、服务网格、多地域、读写分离。
- Redis/Kafka/Elasticsearch 作为默认基础设施。
- 多 Agent 自主规划、无限循环、模型投票和自动执行。
- 通用富文本编辑器、白板、知识图谱、社交协作。
- 为所有未来数据创建 `extra JSONB` 万能字段或动态表单引擎。
- 为尚未选择的功能预建 disabled 菜单、空接口和 feature flag。

## 10. Backlog 提升流程

当用户决定实现某项候选时：

1. 从本文件复制该条目的事实，不直接把整段当需求。
2. 用真实样本确认主流程、失败路径和明确不做。
3. 更新 `PRODUCT.md`（长期事实变化时）与新的版本基线。
4. 更新架构、数据、API、安全、UX 和验收中真正受影响的部分。
5. 用户确认后才创建代码、依赖、迁移或 UI 入口。
6. 完成后从 Backlog 移出，并在版本文档记录实际范围。

这个流程的目的不是增加文档仪式，而是阻止一句“以后可能用”悄悄演变成长期维护的架构。
