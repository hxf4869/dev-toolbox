# 开发百宝箱第二期工具箱总基线

状态：**V2.0–V2.2 已实现并以 `v2.2.0-rc.1` 发布候选部署；稳定版门禁尚未完成**

最后更新：2026-09-01

## 1. 文档目的与权威范围

本文是第二期唯一的产品范围基线，回答以下问题：

1. 第二期到底交付哪些工具，按什么顺序交付。
2. 每个工具能做什么、不能做什么，输入和结果经过哪里。
3. 哪些能力必须在浏览器本地完成，哪些能力允许调用现有服务或阿里云。
4. 多个开发 Agent 可以在什么目录内自主实现，什么变化必须先停下来确认。

本文不把一期冻结文档改写成“包含二期”。一期历史事实、发布证据和知识模块语义继续由 `00-V1-BASELINE.md` 与 `08-V1-ACCEPTANCE-REPORT.md` 负责。本文只在明确列出的第二期范围内覆盖一期的未来候选和排除项：

- 二期允许在工具箱页面使用浏览器端 Monaco、CodeMirror 6 和 Tesseract.js；这些依赖不得进入知识模块首屏。
- 二期允许 OCR，但只属于独立的 OCR 工具，不给知识记录、附件索引或 AI 图片任务增加 OCR。
- 二期把工具箱从候选方向提升为正式模块，但仍然只使用仓库内编译期模块，不建设插件系统。

发生冲突时按以下顺序处理：

1. 用户当前明确要求。
2. 根目录 `AGENTS.md`。
3. 本文。
4. `10-V2-TOOLBOX-ARCHITECTURE.md` 至 `14-V2-AGENT-RUNBOOK.md` 中的专题契约。
5. 一期冻结文档中未被本文覆盖的约束。
6. `PRODUCT.md`。
7. 代码现状。

实现 Agent 不得用 Stitch 示例、依赖库默认行为、个人偏好或“以后可能需要”扩大本文范围。

## 2. 第二期目标与成功标准

第二期把“开发百宝箱”从几乎全部服务于笔记的应用，调整为一个包含两个平级业务模块的个人工程工具：

- **知识与记录**：一期已经完成的保存、搜索和 AI 整理能力。
- **工具箱**：无历史负担、可快速打开使用的确定性本地工具，以及两个额度受控的在线工具。

第二期成功意味着：

- 登录后的 `/` 是中立入口，不再等同于知识工作台。
- 用户可以通过 `/tools/<tool>` 直接进入每个工具。
- 八个本地工具的输入与结果默认只存在于当前页面内存，不上传、不落库、不进 URL。
- JSON/YAML 等大文本处理不会阻塞主线程；重型编辑器和 OCR 模型不会进入首页初始包。
- 阿里云翻译和 OCR 在任何真实调用前都明确显示发送内容、预计额度和实际服务。
- Dev Toolbox 自己的月度硬额度用尽后停止，不提供“继续付费”旁路。这只能约束本应用的调用；阿里云账号下其他凭据/应用共享产品额度时，owner 必须人工对账或把应用上限设得更低。
- 手机端不强行运行不受支持的 Monaco，而使用 CodeMirror 6 或普通移动表单完成同一业务能力。
- 一期知识模块的数据模型、原始事实层和 AI Artifact 语义不因工具箱而改变。

## 3. 冻结决策总表

| 主题 | 第二期决定 | 明确不做 |
|---|---|---|
| 产品结构 | “知识与记录”与“工具箱”平级；AI 任务、设置、帮助仍是全局能力 | 不把所有入口继续塞进知识工作台 |
| 入口 | `/` 为中立首页；工具使用独立 `/tools/...` 路由 | 不做统计大屏、推荐流或最近活动平台 |
| 扩展方式 | 仓库内编译期模块 | 动态插件、manifest 扫描、用户脚本、插件市场 |
| 身份 | 所有页面继续要求当前单实例所有者登录 | 匿名公开工具、多用户、角色、租户、RBAC |
| 默认数据状态 | 工具输入和结果仅在当前标签页内存 | 历史、收藏、自动草稿、同步、分享到 URL、自动保存为笔记 |
| 本地工具后端 | 不创建 API、数据库表或后端任务 | 为统一而增加万能 tools API、工具微服务或第二数据库 |
| 编辑器 | 桌面 JSON/YAML 使用 Monaco；手机使用 CodeMirror 6；按设备只加载一种 | 修补 Monaco 以“支持”手机、全站预加载两个编辑器 |
| 重计算 | 浏览器 Web Worker；显式操作或有界 debounce | 大输入每次按键同步 diff/schema/类型生成 |
| JSON AI | 本地 Java/TypeScript/Go/Kotlin 为默认；用户可显式选择 AI 生成其他语言 | 默认上传 JSON、通用 AI 工具平台、自动执行生成代码 |
| 翻译 | 阿里云机器翻译，通用版优先，必要时自动切专业版 | 用通用 LLM 冒充默认翻译引擎、免费额度外继续付费 |
| OCR | 本地 Tesseract.js 默认；用户明确点击后才使用阿里云 OCR | 自动上传、后台静默切云、实时相机、批量、PDF OCR |
| 云服务配置 | 一套 Dev Toolbox 专用最小权限 RAM 凭据；翻译/OCR 分开计量 | 浏览器保存密钥、自定义 endpoint、多云抽象层 |
| 配额 | 应用级月度硬额度，Asia/Shanghai 月份；无结转 | 自动超额、充值入口、复杂套餐/账单/订阅体系 |
| 云调用并发 | owner 默认 1、范围 `1–3`；全局默认 3、范围 `1–10`；全局不小于 owner；后台可设置 | 前端写死、无界队列、新增多用户/RBAC |
| 基础设施 | 保持 gateway、api、ai-worker、postgres 四个现有服务 | Redis、队列服务、OCR 容器、Kubernetes、新微服务 |

## 4. 版本拆分

### 4.1 V2.0：本地工具箱

按一个里程碑交付八个本地工具：

1. Base64
2. JSON 工作台
3. URL 编解码
4. JWT 检查与验签
5. 时间与 Cron
6. 哈希摘要与校验和
7. 正则测试
8. YAML 工作台

V2.0 同时完成中立首页、工具箱导航、桌面/手机响应式骨架和工具内容隐私基线。

JSON 的可选 AI 类型生成也属于 V2.0，但它是显式在线增强：没有可用 AI Provider、用户不确认发送或调用失败时，本地四语言生成仍必须完整可用。

### 4.2 V2.1：在线文本翻译

交付阿里云机器翻译配置、额度、并发/短队列、技术文本保护、长文本分块和可恢复的顺序调用。“可恢复”只指当前页面内存中从失败片段继续，刷新或关闭后不可恢复。

V2.1 不包含 OCR、翻译历史、词典管理、术语库编辑或文档文件翻译。

### 4.3 V2.2：OCR 与 OCR 翻译

交付单图片本地 OCR、可编辑校对、用户明确选择的阿里云重识别，以及确认后的文本翻译。

V2.2 不把译文重新绘制到图片上，不保存图片或结果，不支持 PDF、批量和实时相机。

里程碑必须顺序集成；可以并行开发互不重叠的模块，但不得在 V2.0 未稳定前把云服务逻辑混入本地工具核心。

## 6. 所有工具共同遵守的规则

### 6.1 内容生命周期

- 输入、结果、临时密钥、期望校验值和编辑器模型默认只在当前页面内存中存在。
- 页面刷新、标签页关闭或主动清空后不可恢复。
- 不写入 `localStorage`、`sessionStorage`、IndexedDB、Service Worker cache、Pinia 持久化或服务器数据库。
- 可以在本机持久化无内容偏好，例如主题、上次目标语言、编辑器换行开关；不得持久化正文和结果。
- 不提供“保存到知识与记录”。用户如需保存，显式复制后自行进入知识模块；V2 不建设跨模块保存链路。
- HTTP、浏览器诊断和应用日志不得记录请求正文、结果、图片、JWT、密钥或完整上游响应。
- 阿里云 AccessKey 是这条默认内存规则的唯一配置例外：由 owner 在设置页输入后，复用现有应用主密钥/secretbox 加密持久化；浏览器永不读回 Secret，也不与 AI Provider 凭据混用。

### 6.2 本地与在线边界

- 每个页面标题旁持续显示“浏览器本地处理”或“云服务”。
- 本地转换、校验、对比和四语言类型生成不得为了遥测、格式化、错误上报或“更准确”调用 API。JSON 页面的“使用 AI”是用户显式启用的独立在线增强，不改变默认本地路径。
- 在线工具在输入区附近说明哪些内容仍在本地、哪些内容将在确认后发送到哪个服务。
- 禁止静默降级到另一种在线服务；唯一确认的自动切换是阿里云机器翻译通用版额度不足时切换专业版。

### 6.3 交互

- 每个视图最多一个实心主操作。
- 粘贴、复制、清空、交换必须有可见文字或可访问名称，不能只靠图标。
- 校验错误给出位置、原因和下一步；不得只显示红框或通用“处理失败”。
- 处理超过 300 ms 才显示进度；允许取消的操作必须在 UI 和 Worker/API 两侧真正响应取消。
- 工具内容不自动执行，不自动访问解析出的 URL，不自动下载，不写剪贴板，除非用户点击复制。

### 6.4 通用输入上限

以下是产品上限，不是可由后台随意放大的部署参数：

| 类型 | 上限 |
|---|---:|
| Base64 文本 | 5 MiB UTF-8 输入 |
| JSON/YAML 单个编辑面 | 5 MiB UTF-8 |
| URL 文本 | 1 MiB UTF-8 |
| JWT token、PEM、JWK/JWKS 单项 | 1 MiB UTF-8 |
| 正则测试文本 | 1 MiB UTF-8 |
| 时间/Cron/自然语言输入 | 16 KiB UTF-8 |
| JSON AI 外发 payload | 256 KiB UTF-8 |
| 单次文本翻译运行 | 原文与保护后最终 payload 各不超过 950,000 UTF-16 code units；最终最多 191 个 chunk |
| OCR 图片 | 5 MiB，最长边 4096 px |

哈希工具的单文件不设低于浏览器 File API 的虚构固定上限，它是受当前设备资源限制的 best effort；固定按 4 MiB chunk 分块读取、持续显示进度、支持取消，不能把整个文件读入内存。

## 7. V2.0 工具契约

### 7.1 Base64

**做什么**

- 只处理 UTF-8 文本。
- 显式选择标准 Base64 或 Base64URL。
- 显式选择编码或解码。
- 提供粘贴、复制、清空和交换输入/结果。
- 显示字符数、UTF-8 字节数和结果大小。

**容错规则**

- 解码时可以忽略复制产生的 ASCII 空白。
- Base64URL 可以省略尾部 padding。
- 非法字符、非法长度、模式不匹配或无效 UTF-8 必须报错。
- 不反复自动解码，不猜测模式，不静默修改输入。

**不做**

- 文件 Base64、图片预览、Data URL 构建、批量转换。
- “加密/解密”术语、密钥、密码保护或混淆功能。

### 7.2 JSON 工作台

一个路由内包含五个页签，并共享当前标签页内存中的输入：

1. **格式化**：格式化、压缩、严格校验、复制结果。
2. **JSONPath**：只读查询、匹配路径、匹配数量和导出匹配值。
3. **对比**：结构对比与文本对比。
4. **Schema**：Draft 2020-12 校验和从当前 JSON 生成初始 Schema。
5. **类型生成**：本地确定性生成或用户明确选择 AI。

**无损数字**

- 解析、格式化、压缩、JSONPath、diff、Schema 和类型生成都不得先把数字转换成 JavaScript `number`。
- 超出安全整数的整数和高精度小数必须按原始词法值保留。
- 不把数值悄悄改成字符串；输出 JSON 仍保持数字 token。

**非标准 JSON 修复候选**

- 只对注释、尾随逗号、单引号字符串和普通未加引号键生成候选。
- 必须展示修复差异，用户点击“应用修复”后才替换输入。
- `undefined`、`NaN`、`Infinity`、函数、正则字面量或其他 JavaScript 表达式直接拒绝。
- 不调用 AI 猜测缺失字段或业务语义。

**JSONPath**

- 只允许数据查询表达式；禁止脚本执行、动态 `eval` 和写回修改。
- 显示每个匹配值的规范路径和总数。
- 查询错误定位到表达式位置，不修改原 JSON。

**对比**

- 文本视图按实际字符/行比较。
- 结构视图忽略空白和对象键顺序。
- 数组默认按索引比较；用户可以显式输入身份字段，例如 `id`。
- 不自动猜测数组身份字段，不把重复身份值合并。

**Schema**

- 只支持 JSON Schema Draft 2020-12。
- 支持粘贴 Schema 校验当前 JSON，以及从当前 JSON 生成一份可编辑的初始 Schema。
- 禁止网络和远程 `$ref`；只解析当前文档内 `$ref`。
- 如实例含任一无法安全映射为 JavaScript number 的数值，为避免 Ajv 产生错误结论，本次只校验 Schema 本身，整份实例校验标为 `not_run_precision_guard`；不做部分通过、强转数字或自研任意精度 Schema 引擎。
- 生成 Schema 只根据当前样本结构，不宣称推断出完整业务约束。

**本地类型生成**

- TypeScript：一个明确的 `interface` 风格。
- Java：普通类，不引入 Lombok/Jackson 注解。
- Go：`struct` + `json` tag。
- Kotlin：`data class`。
- 字符串中的日期、UUID、枚举、URL 等默认仍为字符串，不做语义猜测。
- 字段缺失/可空只根据样本中真实结构确定；单样本不能证明可选时不得虚构业务规则。
- 根值只支持 object 或 array；标量根在本地模式返回 `TYPE_ROOT_UNSUPPORTED`，不伪造包装字段。根 array 分别生成 TS/Go/Kotlin 的 `Root` 类型别名和 Java `Root extends ArrayList<T>`；空数组元素使用各语言通用类型。
- 数组会检查当前样本的全部元素：对象字段在任一元素缺失则标为 optional，在任一元素为 null 则标为 nullable；互不兼容的混合元素退为 TS `unknown`、Java `Object`、Go `any`、Kotlin `Any?`，不生成复杂 union 或猜主类型。
- JSON integer/non-integer 分别映射为 Java/Kotlin `BigInteger`/`BigDecimal`；Go 数字统一 `json.Number`；TypeScript 为 `number`。这是类型声明，不得在生成前把原始数字词法值转成 JS number。
- 字段按首次出现顺序输出。TypeScript 对非法标识符使用原始字符串键；Go 使用稳定清洗后的导出名和精确 `json` tag；Java/Kotlin 使用稳定清洗名并在改变名称时写 `JSON key` 注释。清洗冲突按首次出现顺序加 `_2`、`_3`，不能丢字段。
- nested type 名从 `Root` 加 JSON 路径稳定生成；相同输入、语言和版本必须逐字得到相同输出。输出包含所需标准库 import，不引入第三方运行时。
- Java/Kotlin 对被清洗的 JSON key 只保留注释，不承诺某个序列化框架可直接 round-trip；UI 把本地结果标为“类型骨架，请按项目序列化框架调整”，不得暗示已经编译或运行验证。

**可选 AI 类型生成**

- 用户可以选择任意目标语言文本和现有已启用的 AI 模型。
- 默认发送“结构模式”：属性名、数组/对象关系、原始 JSON 类型，不含字段值。
- “发送完整 JSON”需要二次确认并在确认层预览准确发送内容。
- 最多发送 256 KiB；超限时提示缩小样本，不自动截断。
- 返回内容只作为普通代码文本展示和复制，不执行、不编译、不保存、不转成 AI Artifact。
- 没有 Provider 时只禁用 AI 选项，不影响本地四语言。

### 7.3 URL 编解码

**做什么**

- 显式选择“完整 URL”或“URL 组件”进行百分号编码/解码。
- 解析并展示 scheme、host、port、path、query、fragment。
- Query 参数用表格查看、编辑、增删并重新构建 URL。
- 重复 query key 必须保留顺序和重复项，不能折叠成对象丢失信息。

**严格边界**

- 非法 `%` 转义报错并定位。
- 不反复自动解码，不静默规范化大小写、路径、斜杠或 query 顺序。
- 不自动打开解析出的地址。

**不做**

- Punycode/IDN 转换、URL 规范化、签名、短链接、二维码、网络探测。

### 7.4 JWT 检查与验签

**做什么**

- 本地解析 Header、Payload 和签名段，清楚区分“已解码”和“签名已验证”。
- 支持 `HS256/384/512`、`RS256/384/512`、`PS256/384/512`、`ES256/384/512`。
- 明确拒绝 `alg: none`；V2.0 不支持 EdDSA。
- 临时接受共享 secret、PEM、JWK 或粘贴的 JWKS；密钥只在内存。
- 对 JWKS 使用 Header 中的 `kid` 精确选 key，并校验 `alg` 与密钥类型。
- 缺少 `kid` 或匹配多个 key 时要求用户手动选择，不逐个尝试。
- 显示 `exp`、`nbf`、`iat` 的解析值；用户可选期望 `iss`、`aud`、`sub` 和时钟容差。
- 签名结果与 claims 结果分开显示。

**不做**

- JWT 签发、签名、密钥生成、远程 JWKS URL、自动下载公钥、Token 历史。
- 把“可解码”显示为“可信”或“登录有效”。

### 7.5 时间与 Cron

同一路由页签：时间转换、日期计算、工作日、Cron、自然语言。

- 支持 Unix 秒/毫秒、ISO 8601、UTC、本地时间和 IANA 时区互转。
- 显示当前时间并允许复制，不在后台高频刷新不可见页面。
- 日期计算支持加减年/月/日/时/分/秒和两个时间差。
- 工作日默认周一至周五；用户可在当前页面手动添加节假日和补班日。
- 不内置或联网更新中国法定节假日表。
- Cron 必须显式切换 Unix/Linux 5 段或 Spring/Quartz 6–7 段，不自动猜测。
- Cron 只解释字段并计算未来执行时间；绝不创建、保存或执行定时任务。
- 自然语言只做本地确定性中英文常用表达，例如“明天下午 3 点”“下周一”“3 天后”和 `tomorrow 3pm`。
- `03/04` 等歧义输入必须要求用户明确格式；不调用 AI 猜测。
- 所有结果显示使用的基准时间与时区。

### 7.6 哈希摘要与校验和

**做什么**

- 支持文本和单个本地文件。
- 算法：SHA-256、SHA-384、SHA-512；兼容模式 MD5、SHA-1。
- MD5/SHA-1 持续显示“仅用于旧校验和兼容，不安全”。
- 文件按块读取，不上传、不整体载入内存；显示进度、已处理字节、速率和取消。
- 允许粘贴期望校验值，规范化大小写和可选前缀后做精确比较；结果显示相同/不同和算法。

**不做**

- 目录、批量文件、重复文件扫描、上传、HMAC、密码哈希、加密、签名。

### 7.7 正则测试

- 语法固定为浏览器 JavaScript `RegExp`，页面持续标注“JavaScript 正则”，不冒充 Java/Go/PCRE。
- 支持 flags、全局匹配、匹配范围、捕获组和替换预览。
- 正则执行放在一次性 Web Worker 中；单次执行超过 500 ms 终止 Worker 并显示“表达式运行超时”。
- 用户修改后可以再次显式运行；不得在超时后自动重试。
- 不允许注入或执行 JavaScript 函数、回调源码或任意表达式。
- 不做 RE2 模式、服务端 Java 正则、正则生成器或 AI 自动修复。

### 7.8 YAML 工作台

- 纯 YAML 1.2 工具：YAML ↔ JSON、格式化、校验、行列错误、多文档 `---`。
- 编辑和格式化 YAML 时尽量保留当前文档中的注释。
- JSON 本身没有注释；YAML 转成复制出的 JSON 后再转回不能恢复注释，UI 必须说明。
- 支持普通 anchors/aliases；调用 YAML 库转 JS/JSON 时 `maxAliasCount` 固定为 100，超过时拒绝，避免展开节点放大。
- 重复 mapping key、merge key、`%TAG` 和非标准自定义 tag 拒绝；YAML 时间戳保留为字符串，不自动构造 `Date`。
- 禁止自定义 tag 构造任意对象或执行代码。
- 大整数和高精度数字遵循 JSON 工作台的无损规则。

**明确不做**

- Kubernetes Schema、Kubernetes 资源关系、Helm、集群连接、远程 Schema、任意自定义 tag。

## 8. V2.1 文本翻译契约

### 8.1 主流程

1. 用户输入或粘贴文本，源语言默认自动检测，也可手动覆盖；目标语言默认中文，也可改选其他语言。只有源/目标都是明确语言时才允许交换。
2. 浏览器本地识别并保护 Markdown 结构、围栏代码、内联代码、URL、路径和命令。
3. 浏览器按段落/句子寻找安全边界，再把相邻短段尽量合并；必要时使用硬边界。每个最终 `SourceText` 为 `1–4999` 个 UTF-16 code unit，不得从 surrogate pair 中间切断；单次运行原文和保护后的最终 payload 各不超过 950,000 units，最终最多 191 个非空 chunk。
4. 页面直接显示总计费字符、请求数和目标语言；用户可主动打开“查看发送范围”检查最终 payload，该预览不调用云端。
5. 用户点击“翻译”后执行额度与引擎预检；预检通过即申请云调用并顺序发送片段，不再弹出二次确认。
6. 成功片段立即保留在当前内存结果；失败只恢复失败片段，不重跑成功片段。
7. 全部完成后显示实际使用的每个引擎和剩余额度。

### 8.2 引擎与额度

- 默认使用机器翻译通用版。
- 通用版应用硬额度默认 950,000 字符，允许实例所有者设置 `1–1,000,000`。
- 专业版独立计数，默认 950,000 字符，允许设置 `1–1,000,000`。
- 一个已分好的云 chunk 请求在通用版剩余额度不足时，可以把该整个 chunk 切换到专业版；同一 chunk 不拆成两个引擎结果。一次长文运行的不同 chunk 可以按预检计划分别使用通用/专业版。
- 专业版的 `Scene` 必须由实例所有者在设置页明确选择，只允许阿里云公开的 `title`、`description`、`communication`、`medical`、`social`、`finance`。
- 六个 Scene 只显示阿里云官方含义；`communication` 是“买卖家沟通（电商）”，不是工程技术场景。阿里云没有工程记录专用 Scene，页面不得自行推荐或改名。
- 通用版开放官方冻结的 214 个可用语言代码；专业版只能使用所选 Scene 的明确有向语言对。若计划需要专业版，源语言不能保持 `auto`，必须由用户明确选择；精确清单、矩阵与唯一数据源见 `11` 第 2.1.1 节。
- 未配置专业版场景时，通用版仍可用；自动切换必须在云调用前停止并引导到设置页，不得猜测场景。
- 专业版不足时在调用前硬停止。
- 月份按 `Asia/Shanghai` 的自然月惰性切换，不运行月末定时任务，不结转。
- 额度是应用保护线，不声称实时等于阿里云控制台。专用 RAM 凭据只避免这套凭据被其他程序共用，不会分离主账号下其他凭据的同产品调用；有外部使用时由 owner 人工对账并调低本应用上限。

计费字符和分块统一按 UTF-16 code unit 计数：浏览器使用 JavaScript `string.length`；Go 必须实现相同口径，不能使用 UTF-8 字节数或 Unicode rune 数。

### 8.3 并发与短队列

- 当前 owner 同时占用云 permit 默认 1、可设 `1–3`；全局默认 3、可设 `1–10`，且全局必须不小于 owner。
- 配置保存于后端并由后端强制；当前只有一个 owner，不因“单用户”把数值写死在前端，也不新增角色/租户。
- 当前单 owner 且 `global >= owner` 时，全局值不会先于 owner 值生效；保留两项是用户明确确认的 V2 例外，不得为了让全局值“有用”创造第二用户或新的调用来源。
- 短队列在 Go 进程内实现，只保存 ticket 元数据，不保存文本/图片；最多等待 20 个 ticket。
- 一次翻译运行持有一个 permit，片段顺序调用；具体到期、取消和重启语义以 `10`/`11` 为准。

### 8.4 技术内容保护

- 保护器用占位符替换不应翻译的片段，只把自然语言片段发送给阿里云。
- 占位符必须包含当前请求内随机标识，不能与原文中的普通字符串碰撞。
- 翻译返回后必须验证每个占位符数量、顺序和内容，再还原。
- 占位符丢失、重复、改写或顺序非法时，该片段标记失败并保留原文；不得返回已损坏的混合结果。
- 不使用 AI 猜测如何恢复。

### 8.5 失败与重试

- 浏览器断线前尚未发送的片段不消耗额度，可继续。
- 已明确被上游拒绝且未发送成功的请求释放预留。
- 请求已经发出后出现超时、连接中断或无法确认上游是否受理时，状态为“结果不确定”；该预留保守计入已用，禁止自动重试和自动切换引擎。
- 用户稍后只能手动重试失败片段；UI 必须提示可能重复计费。
- 不做后台任务恢复；刷新页面后正文和结果消失，额度元数据仍保留。

### 8.6 不做

- 翻译历史、记忆库、术语库编辑、文件/文档翻译、网页抓取、字幕、语音、自动保存。
- 使用专业版以外的隐藏降级引擎。
- 在没有用户确认时进行语言检测专用 API 调用；优先使用翻译响应自带的检测语言。

## 9. V2.2 OCR 与 OCR 翻译契约

### 9.1 输入

- 单张 PNG、JPEG 或 WebP。
- 入口：剪贴板粘贴、拖放、文件选择。
- 最大 5 MiB，最长边 4096 px；宽和高都必须大于 15 px，长边与短边之比必须小于 50。只对超过 4096 px 的图片在浏览器本地等比缩小；过小或过于狭长的图片直接拒绝，不自动放大、裁切或补边。本地 OCR 路径不上传原图；只有用户明确选择§9.3 的阿里云重识别时上传调整后的当前图片，两条路径都不保存图片。
- 不支持 PDF、HEIC、TIFF、批量文件、实时相机或视频。

### 9.2 本地 OCR 默认路径

- 默认引擎为 Tesseract.js/WASM，只加载简体中文和英文。
- 默认混合语言；用户可以显式切换英文-only。
- 只启动一个 OCR Worker，按路由懒加载，完成后短时复用，离开页面或空闲超时后终止。
- 显示模型下载、识别进度和取消；说明计算发生在当前设备，不消耗服务器 CPU/内存。
- 低置信度行必须用文字和标记提示，结果可编辑。

### 9.3 阿里云 OCR 可选路径

- 只有用户点击“使用阿里云重新识别”并在确认层看到图片名称、大小、预计 1 次、剩余额度和接收方后才上传。
- 本地低置信度或失败只展示按钮，不自动触发云 OCR。
- 应用硬额度默认 190 次，允许设置 `1–200`；达到上限前原子预留 1 次。
- 结果不确定时按已使用 1 次处理，不自动重试。
- 云 OCR 只返回当前请求结果；服务器不写图片文件、不创建附件、不保存 OCR 文本。

### 9.4 OCR 后翻译

1. 先显示可编辑 OCR 原文和低置信度行。
2. 用户可以只复制 OCR 结果并结束。
3. 用户修正并点击“确认文字并继续翻译”后，才进入 V2.1 文本翻译预检。
4. 点击翻译意味着 OCR 文本将发送给阿里云机器翻译，即使图片识别本身使用本地引擎；UI 必须再次说明这个边界。

### 9.5 不做

- 版面还原、表格专用 OCR、身份证/银行卡/票据专用识别、二维码、手写专项、公式、译文回绘图片。
- OCR 历史、图片库、附件复用、知识库索引、后台批处理。

## 10. 明确非目标

第二期不得顺手加入：

- 动态插件、工具 SDK、工具 manifest、远程加载模块、低代码工具生成器。
- 多用户、团队额度、用户账单、角色、租户、配额购买。
- Base64 文件转换、二维码、加密工具箱、密码生成器、Secret 管理器。
- JSON 编辑协作、在线分享、持久化草稿、远程 `$ref`、自动业务语义推断。
- JWT 签发或远程公钥获取。
- Cron 执行器、任务调度平台、服务器时间同步。
- Kubernetes/Helm 任何专用能力。
- 文档翻译、PDF OCR、相机扫描、批量 OCR。
- 新常驻容器、Redis、消息队列、对象存储、搜索引擎或第二数据库。
- 把本地工具输入写入知识条目、AI 任务或通用审计正文。

## 11. 变更控制

以下变化必须先更新本文并取得用户确认：

- 增删十个已确认工具，或改变 V2.0/V2.1/V2.2 里程碑归属。
- 把本地工具内容发送到服务器或第三方。
- 增加历史、自动保存、分享链接或跨设备同步。
- 增加新云供应商、自定义 endpoint 或自动付费路径。
- 改变阿里云硬额度上限、自动切换规则或“结果不确定”计量方式。
- 增加运行服务、数据库、缓存、消息队列或动态插件机制。
- 让 OCR 进入知识记录/附件流水线。
- 让 JSON AI 能执行、编译、保存代码，或演变成通用 AI 工具平台。

低风险实现细节可以由对应模块 owner 决定，但必须符合专题契约、现有设计令牌和本文件的“做/不做”。

## 12. 基线完成定义

只有同时满足以下条件，才可以把某个版本标记为完成：

- 对应工具的主流程、错误、取消、空、超限和移动状态均已实现。
- 本地工具经过测试证明不会产生 API 请求或内容持久化。
- 在线工具经过本地 mock 证明配额、预留、失败和不确定状态正确；默认测试没有真实阿里云调用。
- Stitch 规范 Screen ID 已按 `12-V2-TOOLBOX-UX-AND-STITCH.md` 使用，生成 HTML 没有被复制为生产代码。
- 对应验收项实际执行并记录；未运行的检查不写成通过。
- 文档没有把尚未实现的后续版本描述成当前可用。
