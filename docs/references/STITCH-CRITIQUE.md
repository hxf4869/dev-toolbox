评审对象：[Stitch 项目 10575442033726834971](https://stitch.withgoogle.com/projects/10575442033726834971)

## 2. 总体判断

结构是为本产品而作，视觉仍偏通用 IDE/知识库。三栏、命令内容、敏感遮挡、原始/整理页签、AI 版本和风险提示证明产品方向正确；但“不可变原始事实 → 可重建 AI 派生层”只表现为普通同级页签，还没有成为产品独有的可信视觉语法。

这不是需要推倒重画的稿，而是一张值得保留方向、进行第二轮收敛的母版。最值得成为产品签名的不是更多装饰，而是来源链、只读状态、安全复制与风险确认。

## 3. 已经成立的部分

1. 三栏工作模型正确：目录、搜索结果和详情同时存在，适合高频查找、比较与复制。
2. 视觉克制统一：蓝色选择、橙色风险、绿色状态各有角色，没有渐变、玻璃和大面积装饰噪声。
3. 已有可信产品骨架：原始记录入口、AI 版本、敏感遮挡、历史和风险提示均已出现，不是普通笔记应用换皮。

## 4. 优先问题

### P1：原始事实与 AI 派生结果的边界太弱

两者只是同级标签，用户准备复制命令时不能快速确认“这是原文还是 AI 整理”。

实现要求：

- 使用“AI 整理”和“原始记录 · 只读”。
- 顶部持续显示原始记录 ID、来源、采集时间和锁定状态。
- AI 区显示来源记录、版本和生成时间。
- 再生成只能创建新版本。
- 提供快速查看原始证据的动作。

### P1：长命令与高风险复制不够安全

详情有效宽度有限，只有整页复制；路径警告在末尾且缺少证据动作，容易把“生成完成”误解成“内容已验证”。

实现要求：

- 每个代码/命令块独立复制并反馈。
- 支持横向滚动和折行切换。
- 风险提示能定位原始证据。
- 状态使用“AI 整理已完成 · 尚未验证”的准确语义。

### P2：搜索中心性与三栏比例不足

搜索更像中栏筛选，详情在实际内边距后对长命令偏窄。

实现要求：

- 搜索作为全局 command bar，显示范围、结果数、清除和快捷键。
- 栏宽可调并记忆。
- 窄窗口优先折叠目录，不能持续压缩命令正文。

### P2：信息架构混合

原始入口、智能视图、类型筛选和 Agent 整理目录混在一起，用户无法立即理解谁是事实层、谁是整理结果。

实现要求：

- 区分固定视图、目录和标签。
- 收集箱统一命名为收件箱。
- 图片/文件表现为固定类型视图。
- 不创建“Agent 目录”这种把生成者混入人工目录的概念。

### P2：本地化、字号、主题和键盘不成系统

实现要求：

- 除 Linux/Docker/ext4 等术语外统一简体中文。
- 正文至少 14 px，代码 13 px 起。
- 交互目标 40–44 px。
- 图标提供 tooltip/可访问名称和可见焦点环。
- 主题只保留一个明确控件。
- 用 200% 缩放验证。

## 5. 用户视角风险

### 熟练用户

Cmd/Ctrl+K 和三栏顺手，但搜索范围/结果数不可见，缺少结果上下移动和复制当前命令的完整键盘路径；整页复制与固定栏宽会拖慢真实运维复用。

### 初次使用者

无法立即理解“收件箱”是否是不可变原始层；`Structured View / Raw Record` 与中文割裂，“查看原文”又与 Raw Record 重复；`AI Task Completed` 容易被误读为命令已经验证。

### 低视力、键盘优先用户

小字号、低对比次级文字、密集标签和 icon-only 导航有风险；静态稿无法证明焦点环、Tab 顺序和状态播报，三栏在 200% 缩放时可能压缩详情和命令。

## 6. 静态稿观察

- 搜索框下方第二个“挂载”含义不清楚。
- `Relevance / Recency` 一个像按钮一个像文字，应统一为分段控件。
- 太阳和月亮同时出现且无选中状态，主题控件含义不明确。
- 敏感记录标题与标签仍可能泄露语义，需要定义元数据遮挡级别。
- 截图没有明显跨栏漂移或画布裁切，长 UUID 仍在代码块内部。
- 静态图不能证明响应式、键盘、ARIA、hover、加载、错误或真实溢出，后续必须在浏览器验证。
