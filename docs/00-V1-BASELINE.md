# 开发百宝箱一期产品与技术总基线

状态：**已完成并关闭，作为 `v1.0.0` 的冻结范围基线**

正式版本：`v1.0.0`
最后更新：2026-08-30

## 1. 文档目的

这份文档把前期讨论收敛成一期唯一的范围基线，解决三个问题：

1. 一期到底要交付什么。
2. 哪些看起来相关、但一期明确不做。
3. 后续编码 Agent 在什么边界内可以自主决策，什么变化必须先征得用户确认。

“详细”不等于提前实现所有可能性。本基线只把当前真实需求说清楚；没有现实使用者、调用链或验收场景的机制不进入一期。

## 2. 一期目标

一期交付一个可以由用户自托管、可公网安全访问的个人工作百宝箱。第一个模块叫“知识与记录”，重点解决以下问题：

- 保存成本必须接近把内容粘贴到企业微信发给自己。
- 格式混乱的命令、说明、账号信息、截图和附件都能先保存，再整理。
- 搜索比回忆目录更重要，能够用中文词、英文技术词和命令片段找回原文。
- 原始记录是长期事实层，后续项目升级、模型变化和目录调整不能破坏原文。
- AI 可以分类、总结、检查和生成动态结构，但所有结果都是可重建派生物。
- 敏感内容可以保存；何时发送给外部模型由用户明确控制。
- 数据、附件和配置通过 Docker 持久化并具有可验证的恢复路径。

## 3. 一期不是这些产品

- 不是 Notion、Obsidian 或语雀的通用替代品。
- 不是密码管理器、堡垒机、服务器资产管理平台或 SSH 客户端。
- 不是自动化运维平台，不会执行、编排或下发任何保存的命令。
- 不是企业协作系统，不支持多人、权限流、评论、审批或共享空间。
- 不是通用 Agent 平台，不允许用户任意安装工具、Prompt、MCP 或插件。
- 不是通用网盘；普通附件能力只服务于个人资料保存和按名称检索。

## 4. 冻结决策总表

| 主题 | 一期决定 | 明确不做 |
|---|---|---|
| 产品名称 | 开发百宝箱 / Dev Toolbox | 不因第一个模块改成“命令笔记”类窄名称 |
| 发布方式 | GitHub 公开仓库、MIT License | 暂不建设商业授权或双许可证体系 |
| 用户 | 单实例、单所有者 | 注册、多用户、组织、RBAC、租户 |
| 客户端 | 桌面优先 H5/Web | Tauri、原生 macOS/Windows、浏览器扩展 |
| 前端 | Vue 3 + TypeScript + Vite | React、多前端并存、微前端 |
| 核心服务 | Go 模块化单体 | Java 服务、按工具拆微服务 |
| AI 执行 | Node.js/TypeScript 独立 worker | Python AI 平台、coding agent、multi-agent |
| 数据库 | PostgreSQL | Redis、第二业务数据库、独立搜索数据库 |
| 附件 | 本地映射卷，元数据进 PostgreSQL | MinIO/S3 服务、分布式文件系统 |
| 搜索 | 精确、子串、模糊、结构化过滤 | 一期不宣称语义搜索，不启用 pgvector |
| AI 模型 | 用户配置外部 API | 本地 LLM、本地 OCR、本地 embedding 模型 |
| AI 协议 | OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、自定义兼容地址 | 任意脚本式 Provider 插件 |
| 原始数据 | 明文存储、不可被普通更新或 AI 覆盖 | E2EE、数据库字段级全文加密 |
| 网络 | 单一 TLS 边缘暴露 80/443；默认 Caddy，已有受控 Nginx 时 gateway 无宿主机端口；其余服务仅内部网络 | 直接暴露 API、worker、PostgreSQL |
| 身份验证 | 密码 + TOTP、恢复码、90 天可信设备 | 邮箱找回、短信、Passkey、SSO |
| 迁移 | 后续由开发 Agent 执行一次性 Notion 迁移 | 一期产品内 Notion/企业微信导入器 |
| 扩展方式 | 编译期模块 | 动态插件市场、用户上传插件 |

## 5. 核心术语

### 5.1 原始记录（Raw Record）

用户一次粘贴、上传或迁移得到的原始事实。正文、原始附件、来源和采集时间构成不可变载荷。

- 每个知识条目恰好有一个主原始记录；后续内容以补充原始记录追加到同一条目。
- 创建后不提供“覆盖原文”的普通 API。
- 用户可以修改标题、目录、标签、收藏等条目元数据。
- 需要补充或纠正时，新建包含正文、图片、普通文件或混合载荷的补充记录，并按需建立“补充/替代”关系；旧记录与旧附件仍存在，不给旧原始记录追加附件。
- 用户仍拥有永久删除权，但必须走明确的永久删除动作，而不是伪装成编辑。

### 5.2 知识条目（Knowledge Item）

用户在列表和搜索结果中看到的工作对象。一个条目至少关联一个原始记录，也可以关联后续补充记录、附件、人工元数据和多个 AI 派生版本。

### 5.3 派生结果（AI Artifact）

模型对指定原始记录生成的标题、摘要、目录建议、标签、步骤、代码块、警告或图片说明。它具有明确的模型、Prompt 版本、Schema 版本、来源和生成时间。

- 派生结果可以失败、作废、重建、切换版本或删除。
- 派生结果不能成为原始事实的唯一保存位置。
- “当前版本”只是 UI 选择，不覆盖历史版本。
- 派生结果是否覆盖最新原始记录/待分析图片由输入快照实时计算；过期不是持久化生命周期状态，也不会自动删除或停用旧版本。

### 5.4 敏感状态（Sensitivity）

- `sensitive`：明确包含密码、Token、私钥、内部地址或用户认为需要保护的信息。
- `normal`：用户明确认为不包含敏感信息。
- `unknown`：迁移、外部 API 或自动分析无法确认；行为上按敏感处理，直到用户确认。

Web 快速录入必须要求用户在 `sensitive` 与 `normal` 之间选择；`unknown` 不作为普通录入选项。

原始记录保存创建时的 `declared_sensitivity` 作为不可变来源事实；知识条目的当前 `sensitivity` 是展示、PAT 与 AI 策略实际使用的值。新增补充记录时按 `sensitive > unknown > normal` 保守合并，并在同一事务中只自动升级、不自动降级；若系统生成标题随之变为敏感/未知，标题也同步换成安全通用值。用户可以明确改判，改判不覆盖原始声明并记录不含正文的安全事件；AI 只能建议，不能触发自动升级或降级。

### 5.5 模型审阅（Model Review）

模型基于输入内容提出的正确性和风险建议。它不是实验验证、服务器验证或官方文档核验，UI 不得使用“已验证”“正确”“可安全执行”等结论性词语。

## 6. 目标用户任务

### JT-01：快速保存

当用户拿到一段以后可能复用的内容时，可以在工作台直接粘贴，选择是否敏感并保存，不需要先想标题、目录和标签。

验收意图：保存不能被 AI、分类、标题生成或附件分析阻塞。

### JT-02：快速找回

当用户需要挂载磁盘、迁移数据库或复用 Docker 命令时，可以搜索中文描述、技术关键词或命令片段，并按相关性或时间查看结果。

验收意图：即使没有 AI Provider，核心搜索仍然可用。

### JT-03：确认来源后复制

用户找到命令后，可以立即看到它来自原始记录还是 AI 整理、记录时间、敏感状态和风险提示，再按代码块复制。

验收意图：复制效率高，同时不会把“AI 已生成”误解成“命令已验证”。

### JT-04：让 AI 整理但不丢原文

用户可以为一条或一批未整理记录运行分类、结构化和检查任务；任务失败、模型更换或 Schema 升级都不影响原始内容。

### JT-05：保存图片和文件

用户可以保存原始图片和普通文件。图片可在配置视觉模型后生成说明；文件只按名称、标题、标签和目录搜索。

### JT-06：公网访问和恢复

用户可通过域名和 HTTPS 从可信电脑访问。部署主机故障后，可以使用数据库、附件和配置备份恢复到新主机。

## 7. 一期功能范围

### 7.1 身份与会话

#### AUTH-01 单所有者初始化

- 不提供注册页面。
- 首次部署通过 CLI/初始化命令创建所有者账号。
- 用户名固定或可配置；密码必须在服务端使用适合密码的哈希算法保存。
- 初始化完成后，同一实例不允许再创建第二位登录用户。

#### AUTH-02 登录流程

1. 用户输入用户名和密码。
2. 实例尚未绑定 TOTP 时，密码正确后进入限时绑定挑战；绑定并验证成功前不签发普通会话。
3. 已绑定 TOTP 且该设备没有有效可信凭据时，要求输入 TOTP 或一次性恢复码。
4. 用户可以勾选“信任此设备 90 天”。
5. 登录成功后签发服务端可撤销会话。

错误提示不得泄露“用户名存在但密码错误”或“TOTP 正确与否”等可用于枚举的信息。

#### AUTH-03 TOTP 与恢复码

- 使用兼容主流 Authenticator 应用的标准 TOTP。
- 初次登录在密码已验证的 5 分钟绑定挑战中显示二维码和手动密钥，用户输入一次验证码完成确认。
- 生成一组一次性恢复码，只展示一次；数据库只保存恢复码哈希。
- 使用恢复码后立即失效。
- TOTP 绑定后是公网访问的必需第二因素，一期不提供“关闭 MFA”，只提供验证旧凭据后的重置。
- 一期不提供短信、邮箱或客服找回。

#### AUTH-04 可信设备

- 默认有效期 90 天，从签发时计算，不因频繁访问无限续期。
- 凭据只放在 `Secure`、`HttpOnly` Cookie 中。
- 服务端只保存令牌哈希、设备显示名、创建时间、最后使用时间和到期时间。
- 用户可查看设备列表、撤销单台设备或撤销全部设备。
- 修改密码、重置 TOTP 时撤销全部可信设备和活跃会话。

### 7.2 快速录入

#### CAP-01 纯文本录入

- 工作台提供始终可达的快速录入入口。
- 接受纯文本和 Markdown；不要求用户选择语言或结构。
- 必填的是“非空正文或至少一个附件”以及敏感状态；允许图片-only/文件-only 记录。
- 单条原始正文 UTF-8 字节上限为 1 MiB；带附件记录允许正文为空，迁移超限内容必须拆成有关联的补充原始记录，不能截断。
- 标题、目录、标签、备注均为可选。
- `Cmd/Ctrl + Enter` 保存；保存成功后明确反馈并保持继续录入的能力。
- 保存 API 完成即算成功；AI 任务只能异步排队。

#### CAP-02 剪贴板与富文本

- 从网页、终端、IDE 或聊天软件粘贴时，优先保留可读纯文本。
- 一期不构建富文本编辑器，不保存任意外部 HTML。
- 如果剪贴板同时含文本和图片，允许形成一条混合原始记录。
- 代码语言识别不是保存前置条件。

#### CAP-03 图片

- 保留上传文件的原始字节，不压缩覆盖原图。
- 可以额外生成用于列表展示的缩略图；缩略图是可删除派生物。
- 记录宽高、客户端声明 MIME、服务端检测 MIME、SHA-256、大小和原始文件名；预览、响应类型和图片处理只信任服务端检测 MIME，SHA-256 只用于完整性检查与恢复时逐项校验。
- 图片内容搜索依赖后续 AI 派生说明；未分析图片仍可按文件名和人工元数据搜索。

#### CAP-04 普通文件

- 单文件上限 20 MiB，服务端实际接收字节数必须再次校验。
- 单次录入最多 10 个附件、实际总字节最多 100 MiB。
- 一期允许常见文档、压缩包、配置文件等任意普通文件，但始终作为附件下载，不作为服务器程序执行。
- 普通文件不做正文提取、全文索引、预览转码或病毒扫描。
- 搜索字段仅包括原始文件名、用户标题、目录和标签。

#### CAP-05 来源信息

每条原始记录至少保存：

- 来源类型：`web_capture`、`browser_extension`、`api`、`notion_migration`、`wecom_migration`、`system`。
- 采集时间。
- 可选外部 ID、外部路径和外部时间。
- 外部时间可信度：`exact`、`estimated`、`unknown`。

一期 UI 只产生 `web_capture`；其他值用于 API 和后续一次性迁移。

`effective_captured_at` 由服务端确定：`source_created_at` 非空且时间可信度为 `exact`/`estimated` 时采用来源时间，否则采用系统 `captured_at`。UI 同时显示时间来源与可信度，不能把迁移时间误当原始发生时间。

#### CAP-06 补充记录与载荷类型

- 已有知识条目可以追加正文、图片、普通文件或混合载荷；正文可以为空，但必须至少有一个附件。文本和 multipart 入口都创建新的不可变补充原始记录，并复用新建记录的事务、临时文件和附件限制。
- `raw_records.content_kind` 只由服务端根据实际载荷派生，客户端不得指定：仅正文为 `text`；无正文且附件全为图片为 `image`；无正文且附件全为普通文件为 `file`；正文与任意附件并存或图片与普通文件并存为 `mixed`。
- 不增加 item 级 `content_kind`；固定视图直接根据条目元数据与其 ready 附件集合计算。

### 7.3 浏览与管理

#### LIB-01 固定视图

一期提供：

- 原始收件箱：未删除且没有主目录的条目。
- 最近：未删除条目，按有效采集时间倒序。
- 收藏：未删除且 `favorite = true` 的条目。
- 敏感：未删除且当前状态为 `sensitive` 或 `unknown` 的条目。
- 图片：未删除且至少有一个 ready 图片附件的条目。
- 文件：未删除且至少有一个 ready 普通文件附件的条目。
- 回收站：已经软删除的条目。

这些是由现有字段确定性计算的固定查询视图，不是目录；UI 必须用不同视觉语言区分固定视图、目录和标签。不得为其额外增加 `processed`、`archived` 或 `inbox_status` 状态。

#### LIB-02 目录

- 目录是单棵用户可管理的树。
- 每个知识条目一期最多有一个人工生效的主目录。
- 支持新建、重命名、移动和删除空目录。
- 删除非空目录时必须先将条目移回收件箱或选择其他目录；不级联删除条目。
- AI 只生成目录建议；一期默认由用户确认后应用。

#### LIB-03 标签

- 条目可拥有多个标签。
- 标签名称在忽略大小写后唯一。
- 人工标签与 AI 建议标签分开保存；只有用户应用后才进入正式标签。
- 一期不做标签层级、颜色自定义和复杂规则引擎。

#### LIB-04 人工元数据

用户可以修改：

- 条目标题。
- 主目录。
- 标签。
- 收藏状态。
- 一段简短人工备注。
- 敏感状态。

修改这些字段不会创建新的原始记录，也不会改变原始正文。

敏感/未知记录未填写标题时，系统标题必须是“敏感记录 · 时间”这类安全通用值，不能从原文第一行自动摘取密码或 Token。用户明确输入/采纳的标题、目录和标签可在遮挡列表中显示，正文与 AI 摘要默认不显示。

#### LIB-05 删除

- 普通删除先进入回收站。
- 回收站内容不出现在普通搜索和目录中。
- 用户可以恢复或永久删除。
- 永久删除会删除关联原始记录、附件、派生结果和搜索片段；这是唯一允许物理移除原始数据的产品动作。
- 一期不自动清空回收站，避免未经用户决定的数据丢失。

### 7.4 搜索

#### SRCH-01 可搜索来源

一期索引：

- 条目标题。
- 人工备注、目录和标签。
- 原始文本。
- 代码块和命令片段。
- 附件文件名。
- 已激活 AI 派生结果的标题、摘要、标签、目录建议和图片说明。

普通文件正文不索引。敏感内容进入索引以便用户本人搜索，但搜索摘要需要按敏感显示策略遮挡。

#### SRCH-02 查询方式

- 精确短语。
- 大小写不敏感子串。
- PostgreSQL trigram 模糊匹配。
- 英文/数字/代码 token 匹配。
- 目录、标签、类型、敏感状态和时间范围过滤。
- 用户输入按字面文本处理；一期没有布尔表达式、字段语法、引号语法、减号排除、正则表达式或 Lucene 风格 DSL。
- `LIKE/ILIKE` 路径必须转义 `%`、`_` 和转义字符本身。索引与查询使用同一套 Unicode 大小写、换行和普通空白规范化，但保留路径和命令有意义的标点。

一期不得把上述能力命名为“语义搜索”。

#### SRCH-03 排序

- `相关性`：标题精确命中 > 原始内容精确命中 > 人工标签/目录 > 模糊命中 > AI 派生关键词；有效采集时间只在匹配等级与相似度之后参与排序。
- `时间`：按有效采集时间倒序；外部时间未知时使用系统采集时间并明确来源。
- 搜索界面显示当前排序、结果数和搜索范围。
- 两种排序都必须有 `item_id` 等确定性最终排序键；游标编码当前排序使用的完整元组，翻页不得因同分或同一时间而重复、遗漏或漂移。

相关性查询使用固定的离散 `match_class`，不得由 handler 临时调整顺序：`5=title_exact`、`4=fact_literal`（不可变原文、代码或附件文件名的字面命中）、`3=human_metadata_literal`（人工标题、标签、目录或备注的字面命中）、`2=fuzzy`、`1=ai_derived`。同一 class 内再比较 trigram similarity、有效采集时间和 item ID。trigram 候选只由一处代码常量控制最低相似度并用版本化排名 fixture 锁定，不做用户配置或查询语法；未进入 fuzzy class 的短查询仍保留精确、前缀和子串结果。

#### SRCH-04 片段

- 长记录按标题、段落组和代码块生成检索片段。
- 片段只是索引单元，点击结果始终打开所属知识条目并定位到相关位置。
- 分片必须是确定性处理，不依赖模型；重新索引不能改变原文。
- 命中高亮由 API 返回无 HTML 的文本分段及高亮标记，不返回跨 Go Unicode 与 JavaScript UTF-16 语义不明的字符下标；中文、emoji 和组合字符都不能错位或截断。

#### SRCH-05 无结果行为

- 显示当前查询和过滤条件。
- 提供清除过滤、按时间浏览和新建记录入口。
- 不自动调用付费模型改写查询。

#### SRCH-06 查询隐私

- 原始搜索词 `q` 只放在搜索请求正文，不进入 URL、访问日志、`localStorage`、`sessionStorage` 或 IndexedDB；不要求刷新后恢复。当前标签页内存可用于返回列表时恢复现场。
- 固定视图、目录、标签、类型、敏感状态、时间范围和排序等非敏感状态可以写入 URL，以支持刷新和前进/后退。
- 搜索响应统一返回 `Cache-Control: no-store`；Caddy 日志只记录不含查询串的路径，API 日志只记录路由模板，两者都只保留状态、耗时、请求 ID 等安全元数据，不记录请求正文或原始查询词。

### 7.5 详情与复制

#### DETAIL-01 固定外壳

详情区固定提供：

- `AI 整理`。
- `原始记录 · 只读`。
- `附件`。
- `历史`。

页签外壳固定，AI 整理页内部由版本化 block JSON 动态渲染。

#### DETAIL-02 来源栏

原始记录页和 AI 整理页都必须持续显示：

- 条目/原始记录 ID 的短标识。
- 来源类型和来源路径。
- 采集时间。
- 敏感状态。
- 原始记录只读状态。
- AI 版本、模型、生成时间和对应的原始记录。

#### DETAIL-03 命令复制

- Markdown fenced code block 与 AI Artifact 的 `command`、`command_steps`、`code` block 都有独立复制按钮。
- `plain_text` 原文保持整体展示并提供“复制全部原文”；不得用正则、语言识别、Shell parser 或其他启发式把普通文本猜成命令块。用户选择局部文本时仍可使用浏览器原生复制。
- 复制后显示明确成功反馈。
- 支持折行/不折行切换和横向滚动。
- 敏感显示策略启用遮挡时，未揭示内容不可复制。
- AI 生成命令旁始终显示“模型整理，执行前请核对原文”。

#### DETAIL-04 对比和历史

一期至少支持从 AI 版本历史中切换当前版本，并能一键查看该版本的原始来源。

一期不实现字符级 diff 编辑器；“对比”可以通过并排或快速切换实现。

### 7.6 AI 任务

#### AI-01 任务类型

一期只允许以下任务：

1. `organize_record`：生成标题、摘要、内容类型、目录和标签建议、动态 blocks。
2. `review_record`：发现命令中的不一致、缺失前置条件、危险操作和时效风险，输出建议。
3. `analyze_image`：生成图片说明、可检索文本、分类和可能的敏感提示。
4. `batch_organize`：为一批未整理条目按内容创建子任务；有正文时使用 `organize_record`，有待分析图片且视觉模型可用时使用 `analyze_image`，同一混合条目可以同时产生两种子任务；只有普通文件时跳过并报告原因。

新增任务类型必须先更新基线和 JSON Schema，不允许实现 Agent 自由选择任意目标。

#### AI-02 手动与定期执行

- 用户可在单条详情中手动运行。
- 用户可在收件箱选择最多 100 条批量运行；每条仍产生独立子任务和 artifact，单条失败不回滚其他条目。
- 定期整理默认关闭；可选择每日或每周、IANA 时区、本地执行时间，周任务再选择星期；不暴露任意 Cron 表达式。
- 每次定期运行最多选取 20 条记录，按采集时间从旧到新处理，防止首次开启时产生无界模型费用；剩余记录留到下个周期或由用户手动批量执行。
- 定期任务只处理当前 artifact 尚未覆盖最新 raw records/ready 图片集合、或用户明确要求重建的条目；新增补充记录或图片后，对应结果重新变为待整理/待分析。
- 图片是否已处理按当前 `image_analysis` 的任务输入快照判断；未配置视觉模型时只跳过图片分支并在批次摘要说明，不影响同一条目的正文整理。普通文件不做 AI 内容分析。
- 模型费用、失败和限流不能阻塞录入与搜索。
- 当前原始记录在保留系统 Prompt 与最大输出预算后仍放不进所选模型上下文时，任务明确失败并建议换大上下文模型或拆分记录；一期不静默截断，也不自动建设多段 Map/Reduce 总结。

#### AI-03 敏感内容策略

系统设置提供三种策略：

- `block`：敏感/未知记录不发送给外部模型。
- `redact`：使用本地确定性规则替换明显的密码、Token、私钥和地址，再发送脱敏副本；默认推荐。
- `allow`：发送原文，必须由用户主动选择并看见风险提示。

规则脱敏不得宣传为百分之百可靠。脱敏映射仅用于本次任务，不能写回原始记录。

敏感策略覆盖任务的全部输入，不只覆盖当前条目：`block` 下当前条目敏感/未知则拒绝任务，相关记录中的敏感/未知候选直接排除；`redact` 对当前记录、相关记录和图片说明分别处理；`allow` 也只能读取任务数量上限内的明确相关记录。

一期没有本地 OCR/图像打码能力，因此敏感或未知图片在 `redact` 下也不能发送原图，行为等同 `block` 并给出原因；只有记录明确为 normal，或用户主动选择 `allow`，视觉任务才可发送原图。

#### AI-04 模型正确性边界

- `review_record` 只根据当前条目的原始记录和模型知识审阅，不读取其他条目。
- 相关记录只帮助分类和发现相似术语，不能作为当前 artifact 的可引用原始证据，也不能把其中命令复制进当前结果；正式 sourceFragmentId 只来自当前条目的 raw records。
- 一期不提供互联网搜索工具、SSH、Shell、SQL 执行或服务器检测工具。
- 风险提示需要引用输入片段 ID；无法确认时使用“不确定/需核对”。
- UI 状态只能是“待运行、运行中、模型审阅完成、失败、已取消”，不能是“验证通过”。

#### AI-05 结果激活

- 成功任务首先产生候选派生结果。
- 用户可以查看任一历史版本，并激活未作废版本；已作废版本只能查看。
- 当前版本按 `organized_record`、`correctness_review`、`image_analysis` 分开保存；激活一种结果不能覆盖另外两种。
- `organize_record` 可配置“成功后自动设为当前整理版本”，默认开启；这只影响派生视图。
- 内置 `analyze_image` 成功并通过校验后自动设为当前图片分析版本，使图片说明进入搜索；不自动改变目录、标签或敏感状态。用户仍可作废并重新生成。
- `review_record` 默认只产生候选审阅，用户查看后决定是否设为当前审阅版本。
- 目录和正式标签默认仍需用户应用，防止模型重排人工结构。
- 重新生成永远创建新版本。
- 新增补充原始记录或 ready 图片后，现有 active artifact 不自动删除、失效或切换；API 通过输入快照返回计算值 `isStale=true`。
- 所有过期 artifact 仍可查看，未作废版本可由用户主动激活；已作废版本只能查看。只有当前激活版本参与普通搜索，且不会仅因过期退出搜索。搜索结果持续标明命中来自 AI，详情和应用其建议前必须提示“此 AI 版本未覆盖最新原始记录”。
- 定期与批量整理把过期条目视为待处理，但生成新版本前不替用户判断旧结果无效。

### 7.7 Provider 配置

#### PROVIDER-01 支持协议

- `openai-completions`（OpenAI Chat Completions 兼容协议）。
- `openai-responses`。
- `anthropic-messages`。

自定义 Provider 仍必须选择上述一种协议，不允许用户上传执行代码。

#### PROVIDER-02 配置项

- Provider ID：小写稳定标识，创建后不可变。
- 显示名称。
- Base URL。
- API 协议。
- API Key。
- 启用状态。
- 模型列表：模型 ID、显示名、上下文窗口、最大输出 token、是否支持工具调用、是否支持图片。
- 模型可以先以未知限制保存，但只有上下文窗口和最大输出 token 都配置为正整数后才能用于任务。
- 工具调用是可选传输能力，不是任务准入条件；worker 对同一简化 Draft 同时支持工具参数和严格纯 JSON 输出。图片任务仍要求模型支持图片输入。
- 默认整理模型、默认检查模型、默认视觉模型。

模型目录自动获取是辅助功能；失败时必须允许手工维护模型。

#### PROVIDER-03 密钥

- API Key 只在创建/替换时输入，不提供明文查看。
- 数据库保存加密值，界面只显示末尾掩码。
- 测试连接不得把密钥或完整响应记录到日志。

### 7.8 外部 Agent API

#### EXT-01 目的

允许 Codex、其他 Agent 或一次性迁移脚本读取授权数据、提交派生结果和发起任务，避免一期把所有 Agent 能力耦合进 Web 产品。

#### EXT-02 Token

- 用户在设置页创建个人访问 Token，明文只展示一次。
- 数据库只保存 Token 哈希。
- 一期固定 scope：`records:read`、`records:write`、`attachments:read`、`artifacts:write`、`tasks:run`、`sensitive:read`。
- `sensitive:read` 不默认勾选；没有它时敏感/未知条目只能看到遮挡元数据，不能读取原文/附件，也不能为其提交 artifact。
- Token 可设置名称和到期时间并随时撤销。
- `records:write` 只允许新建原始记录，不允许覆盖现有原始记录。

#### EXT-03 派生结果提交

- 外部 Agent 提交的结果必须声明原始记录 ID、生成者、模型/工具信息和 Schema 版本。
- 服务端执行同一 JSON Schema 校验。
- 外部结果默认是候选版本，不自动修改目录和标签。

### 7.9 设置

一期设置包括：

- 外观：深色/浅色/跟随系统，默认深色。
- 登录安全：修改密码、TOTP、恢复码、可信设备和会话。
- 敏感记录显示与外部 AI 策略。
- Provider 和模型。
- 定期整理开关与频率。
- 个人访问 Token。
- 存储用量、版本和备份状态只读信息。

一期不提供任意系统配置编辑器或在线编辑 `.env`。

## 8. 非功能要求

### NFR-01 可恢复性

- 数据库、附件和必要配置缺一不可。
- 上线前必须至少完成一次从备份恢复到空环境的演练。
- 应用升级不能要求用户手工修改数据库数据。

### NFR-02 性能目标

目标规模不是企业级大数据，而是为个人长期使用留出余量：

- 验收数据集：50,000 条原始记录、500,000 个搜索片段、附件总量 20 GiB。
- 在最终部署硬件上，关键词搜索第一页的服务端 P95 目标不超过 500 ms。
- 不含附件上传时，纯文本保存的服务端 P95 目标不超过 300 ms。
- AI 任务不设同步响应时限，只要求状态可见、可取消、失败可重试。

硬件、网络和外部模型不确定时，不得伪造更精确的性能承诺；验收必须记录实际测试环境。

### NFR-03 可用性

- 数据库或附件写入失败时，本次保存必须整体失败，不能出现“列表有记录但原文丢失”。
- AI worker 不可用时，录入、搜索、浏览和附件下载仍可用。
- Provider 不可用只影响对应 AI 任务。
- 浏览器刷新或 API 重启后，已入库任务状态仍可恢复。

### NFR-04 兼容性

- 一期首要支持当前 Chrome 和 Safari 的桌面版本。
- Edge 和 Firefox 不进入一期发布验收矩阵，也不承诺经过验证的兼容性；实现不得主动按 User-Agent 阻断它们，后续是否纳入支持范围由实际使用需求决定。
- 手机浏览器保证登录、搜索和阅读基本可用，不承诺三栏或高效录入。
- 浏览器扩展、PWA 离线和桌面壳不作为一期验收。
- 搜索和快速记录必须始终有可见入口；快速记录快捷键在 M1、搜索快捷键在 M2 对当前 Chrome 和 Safari 完成浏览器 smoke 后分别固定。在固定前契约状态为“待实测”，不得把会触发浏览器常用行为的组合设为发布硬要求。

### NFR-05 可观测性

- JSON 结构化日志，包含时间、级别、服务、请求 ID、稳定错误码和耗时。
- 不记录请求正文、原始全文、附件内容、Cookie、Authorization 或 Provider Key。
- AI 任务保存事件摘要、错误类型、模型、token 用量和耗时；不持久化完整 Prompt 或 Provider 原始响应。
- 提供内部健康检查，区分进程存活、数据库可用和 worker 状态。

## 9. 一期明确排除

以下事项即使实现看起来简单，也不属于一期：

- 通用富文本编辑器、双向链接、知识图谱、白板。
- Notion/企业微信自助导入、同步或导出向导。
- 多用户、分享链接、公开页面、协作编辑。
- 密码生成、自动填充、浏览器密码插件、SSH 凭据注入。
- Shell/SSH/SQL 执行、服务器探测、自动部署、定时运维。
- 本地 OCR、PDF/Office 正文解析、视频音频分析。
- 本地模型管理、GPU 调度、模型下载。
- 向量数据库、RAG 问答、语义搜索、自动联网核验。
- 任意工作流编排器、可视化 Prompt 流程、multi-agent。
- WebSocket 实时协作；AI 任务状态可以使用轮询或 SSE，但不建设通用实时总线。
- 动态插件、第三方插件市场、脚本沙箱。
- 移动 App、Tauri、Electron、浏览器扩展。
- Kubernetes、Helm、多地域、高可用数据库、读写分离。
- 企业级审计、SIEM、DLP、WAF 管理平台。

完整延期清单见 `BACKLOG.md`。

## 10. 防止过度设计的判断规则

编码 Agent 在提出新机制前必须回答：

1. 它解决的是哪个已编号需求或验收失败？
2. 当前简单方案为何无法满足？
3. 一期内谁会调用它？
4. 不实现它会导致什么现实问题？
5. 它是否增加了新进程、新数据库、新密钥、新网络边界或长期维护成本？

如果前四项没有具体答案，就不实现。以下情况默认拒绝：

- 只因为“以后可能多人使用”而增加租户和 RBAC。
- 只因为“以后可能很多数据”而增加搜索集群和消息队列。
- 只因为“以后有很多工具”而增加插件框架和微服务网关。
- 只因为“安全最佳实践”而让核心记录无法搜索、迁移或恢复。
- 只因为模型可能失败而堆叠多模型自动回退、无限重试和复杂补偿。

真实安全边界、数据丢失风险和公开 API 输入不属于“过度防御”，必须按专题文档实现。

## 11. 变更控制

- 修正错别字、补充不改变行为的例子，可以直接更新文档。
- 改变一期范围、运行服务、数据不可变原则、敏感数据策略、认证方式或 AI 权限，必须先说明影响并获得用户确认。
- 新需求未被确认前先记入 `BACKLOG.md`，不得因为实现方便直接进入当前里程碑。
- 专题文档细化总基线时不得改变总基线语义；如果必须改变，应先更新本文。

## 12. 一期完成判定

只有同时满足以下条件才算一期完成：

- `docs/06-DELIVERY-AND-ACCEPTANCE.md` 中所有 V1 必须验收项通过。
- 原始记录、附件和 AI 派生结果的边界经过集成测试验证。
- 未配置 AI Provider 时，录入、搜索、浏览、复制、登录和备份仍完整可用。
- 真实 Docker Compose 环境完成 HTTPS、MFA、可信设备、备份和空机恢复演练。
- UI 对深色、浅色、键盘、200% 缩放、长命令、敏感记录和错误状态完成验证。
- 没有把 `BACKLOG.md` 中的延期能力包装成未完成的“一期入口”。
