## 3. 全局应用壳

### 3.1 桌面

`>= 1280px`：

- 56 px AppRail：产品级入口和全局动作。
- 236 px ModuleNav：当前模块内导航。
- 其余为页面内容；编辑器工作台可以占满内容宽度。

AppRail 固定提供：首页、知识与记录、工具箱、AI 任务、设置、帮助。当前项用背景、左/下标记和可访问状态共同表达，不只换图标颜色。

工具箱 ModuleNav 分三组，且只展示当前已发布工具：

1. 编码与数据：Base64、JSON、URL、JWT、YAML。
2. 开发辅助：时间与 Cron、哈希摘要、正则。
3. 在线能力：文本翻译、OCR 翻译；分别在 V2.1/V2.2 发布后加入。

未发布工具不创建空路由、不显示“敬请期待”占位，也不在首页快捷入口出现。

### 3.2 中等宽度与手机

| 宽度 | 壳层行为 |
|---|---|
| `960–1279px` | 保留 AppRail；ModuleNav 收进可打开 drawer，不继续压缩编辑器 |
| `600–959px` | 使用紧凑顶栏；工具清单由 drawer 打开；内容单主栏 |
| `<600px` | 手机顶栏、明确返回、工具切换 drawer；无常驻左栏，主操作保持可见 |

当前 `ModuleNav` 在小宽度隐藏，V2 必须同时提供可发现的“工具列表”按钮，不能只靠浏览器返回。drawer 打开后焦点进入，第一个可交互项获得焦点；关闭后焦点回到触发按钮。

### 3.3 页面共同头部

每个工具页依次包含：

- 面包屑/返回工具箱。
- 工具名和一句准确用途。
- 持续可见的处理徽标：“浏览器本地处理”“可选 AI 外发”“阿里云云服务”。
- 必要的输入限制说明。
- 清空等次要动作；只有一个实心主操作。

“本地处理”不得只在空状态显示，输入后也不能消失。在线页必须在主操作附近写出接收方和预计额度。

## 4. 中立首页与工具箱入口

### 4.1 `/` 中立首页（Screen 34）

首页只做三个任务：

1. 平级进入“知识与记录”或“工具箱”。
2. 显示当前已发布工具的少量直接快捷入口。
3. 说明本地工具与云工具的边界。

不显示记录数、调用量排行榜、最近活动、推荐流、营销 hero、图表或“效率提升百分比”。一期快速记录入口仍可在知识模块内保持，不占据中立首页主视觉。

### 4.2 `/tools`

使用紧凑工具卡/列表：名称、一句话说明、本地/云徽标、当前可用状态。工具名称和路由固定，不做用户排序、收藏、最近使用或分类编辑。点击卡片直接进入工具；键盘顺序与视觉顺序一致。

## 5. 三种页面母版

### 5.1 简单转换母版（Screen 35）

适用：Base64、URL、JWT 的解析部分、哈希文本模式、正则输入。

- 桌面输入与输出并排；窄屏上下堆叠。
- 模式/算法选项靠近输入，不放在全局设置。
- 主按钮位于输入区末端；结果区复制是次要动作。
- 空结果显示“执行后在此显示”，不预填伪结果。
- 输入错误就地显示位置和原因，保留用户原文。

### 5.2 编辑器工作台（Screens 36/37）

适用：JSON、YAML。

- 桌面使用页签 + 双编辑面/结果面；手机一次只显示“输入”或“结果”。
- 编辑器外仍有真实 `<label>`、工具名称、错误摘要和按钮；不能把全部交互塞进编辑器 command palette。
- 大操作由用户点击；输入时只做有界的基本语法反馈。
- 行列错误既标在编辑器内，也在编辑器外提供可聚焦文本列表。
- 切换页签共享当前内存输入，不复制出五份隐形文档。

### 5.3 任务流母版（Screens 39/40/42）

适用：翻译、OCR 翻译。

任务流固定显示：当前步骤、实际接收方、预计额度、当前月剩余、可取消/重试语义。等待状态不能用无限转圈代替排队位置或片段进度。

## 6. V2.0 各工具 UX

### 6.1 Base64 编码/解码

- 页面术语始终是“编码/解码”，不写“加密/解密”。
- 顶部两个明确控件：操作（编码/解码）、变体（Base64/Base64URL）。
- 交换只交换输入与结果并保留当前模式，不自动连续执行。
- 非法字符、长度或 UTF-8 显示具体错误；不自动切换变体。

### 6.2 JSON 工作台

页签固定为：格式化、JSONPath、对比、Schema、类型生成。

格式化：主操作随模式显示“格式化”或“压缩”；非标准修复只先展示 diff 和“应用修复”。

JSONPath：表达式有独立输入；结果列出规范路径、值和总数。语法子集允许根 `$`、属性/索引、通配、递归、数组切片和并集；不提供执行脚本的过滤表达式。禁用能力要写清，不用一个泛化“无效表达式”。

对比：桌面双输入 + diff，手机输入 A/B/结果分步切换。结构/文本是显式模式；数组身份字段是可选文本框，不默认 `id`。

Schema：Schema 与实例都有明确标签。实例含任一不安全数值时，整份实例校验状态是“未执行：数值精度保护”，只能显示 Schema 本身是否合法；不显示结构部分通过或完全通过。

类型生成：

- 默认分段控件选“本地确定性”。语言只列 TypeScript、Java、Go、Kotlin。
- 选“使用 AI”后才出现 Provider、模型、目标语言和发送模式。
- 结构模式默认；完整 JSON 显示二次确认和逐字发送预览。
- AI 失败后保留输入，并提供返回本地生成；不自动换模型。

### 6.3 URL 编解码

- 显式选择“完整 URL”或“URL 组件”，以及编码/解码。
- 解析区用字段表显示 scheme/host/port/path/query/fragment；query 使用保序行表。
- “重新构建”不自动打开 URL。重复 key 显示为独立行，不折叠。

### 6.4 JWT 检查与验签

结果状态必须分成两行/两卡：

1. 签名：未验证 / 通过 / 失败。
2. Claims：未检查 / 通过 / 已过期 / 尚未生效 / 期望值不匹配 / 格式错误。

默认行为：

- 仅粘贴 token 时只解码，不宣称可信。
- 提供 key 后默认检查签名、`exp` 和 `nbf`；`iat` 只展示，不把未来 `iat` 直接判无效。
- 默认时钟容差 60 秒，可设 `0–300` 秒。
- 缺少 `exp`/`nbf` 不是格式错误，显示“未提供”；存在但类型非法则是 claims 失败。
- `iss`、`aud`、`sub` 只在用户填写期望值后校验。
- JWKS 有精确唯一 `kid` 时使用；无 `kid` 即使只有一个 key 也要求用户确认，多个匹配时要求手选，绝不逐 key 尝试。

总状态不能把“签名通过但已过期”显示为可信。

### 6.5 时间与 Cron（Screen 38）

页签：时间转换、日期计算、工作日、Cron、自然语言。

- 页面始终显示基准时间和 IANA 时区。
- 自然语言 grammar 只覆盖：今天/明天/后天、`N` 天/小时/分钟后、下周一至周日、上午/下午/晚上 + 时分，以及对应 `today/tomorrow/in N days/next weekday` 英文形式。
- 基准是浏览器当前时刻与页面当前选择的 IANA 时区；“下周一”始终指下一个自然周的周一，即使今天不是周一。
- 夏令时导致不存在的本地时间时要求选择向前/向后调整，不静默改写；重复时间显示两个 offset 供选择。
- 未匹配的自然语言返回“暂不支持该表达式”，不调用 AI。
- Cron 预览显示选定方言、时区和未来 5 次；不会出现“运行”或“保存任务”。

### 6.6 哈希摘要与校验和

名称固定为“哈希摘要与校验和”，避免误解为文本总结。

- 文本/单文件切换。
- 文件模式显示名称、大小、算法、进度、已处理字节、速率和取消。
- 单文件是受设备资源和浏览器 File API 限制的 best effort；按 4 MiB chunk 读取，任何时刻不持有整个文件。页面不承诺一个虚假的跨浏览器最大文件值。
- 期望值比较只规范化大小写、ASCII 空白和可选 `0x`，再做精确比较。
- MD5/SHA-1 选择项持续带“不安全，仅兼容旧校验和”。

### 6.7 正则测试

- 页面标题旁持续显示“JavaScript RegExp”。
- flags 使用明确开关；表达式、测试文本和替换模板分别标注。
- 结果显示匹配编号、起止位置、完整匹配和捕获组；替换只预览。
- 500 ms 到期显示已终止，不自动减小文本、改写表达式或改用另一引擎。

### 6.8 YAML 工作台

- 模式：格式化/校验、YAML→JSON、JSON→YAML。
- 支持多文档时用明确文档分隔与编号；JSON 输出多文档时显示数组或逐文档结果，并写明选择的输出形式。
- 重复 mapping key 是错误；不采用“最后一个覆盖前面”。
- YAML 时间戳默认保留为字符串，不自动创建 Date。
- 数字保留大整数/高精度；merge key 与自定义 tag 拒绝。
- 格式化前提示“尽力保留注释，位置可能调整”；原输入只在用户点击后替换。

## 7. V2.1 翻译 UX（Screens 39/42）

### 7.1 输入与语言

- 源语言默认“自动检测”，可手动选择；目标语言默认“中文”，也可改选其他语言。
- 语言选择只读取 `GET /api/v1/aliyun/translation/languages` 的官方冻结清单，不在 Web 另写 code 别名；支持按中英文名或 code 搜索。
- 只有源和目标都为明确语言时，“交换语言”才可用；自动检测状态下点击交换先要求选定源语言。
- 自动检测不单独调用 API；第一次成功翻译后显示上游返回的检测语言。
- 如果额度计划需要专业版而源语言仍是“自动检测”，preflight 在发送前要求用户明确源语言；当前 Scene 不支持明确语言方向时，显示支持范围并引导修改语言或设置场景，不提供“仍然尝试”按钮。
- 输入计数同时显示用户文本字符、最终预计计费 UTF-16 数和 chunk 数；计费以保护/分块后的 `SourceText` 为准。
- 原文或保护后 payload 超过 950,000 UTF-16 units，或合并短段后仍超过 191 个 chunk 时，在确认前显示实际值/上限并停止；不截断，不悄悄拆成第二次运行。

### 7.2 发送范围与主操作

页面提供可选的“查看发送范围”入口，主动打开后显示：

- 接收方“阿里云机器翻译”。
- 源/目标语言。
- 最终发送的自然语言与占位符预览、chunk 数、预计计费字符。

该预览只读取浏览器内存，不执行 preflight、不产生 ticket 或额度。主按钮文案为“翻译”；点击后先执行 preflight，成功则直接排队并发送，不弹出二次确认。额度不足、配置缺失或语言方向不支持时仍在发送前硬停止并显示恢复入口。

### 7.3 排队、运行和恢复

- 排队显示当前位置和 2 分钟到期，不显示虚假百分比。
- 运行显示 `已完成 x / n`、当前片段和已使用引擎；成功片段立即留在当前页内存。
- 每个 chunk 带最新 preflight 计划中的 `expectedEngine`；服务端发现账本变化时在上云前停止。`PREFLIGHT_CHANGED` 只含当前 chunk 事实，浏览器必须把内存中的“当前 + 剩余未发送” `chunkUnits` 和当前语言再次提交 preflight；新计划通过后自动继续，失败则保持停止并显示错误。新计划取得前不重新排队、不预留、不调用 SDK。
- 取消后清楚区分未发送、已发送、结果不确定片段。
- “恢复”只指当前标签页内存中从失败片段继续；刷新或关闭后不可恢复。
- 结果不确定时沿用 Screen 42：说明已经保守计量、结果未收到、不会自动重试；手动重试按钮同时提示可能重复计费。
- 额度不足时没有继续付费或忽略限制按钮，只能等下月、降低本月其他使用或检查设置/控制台对账。

## 8. V2.2 OCR 翻译 UX（Screens 40/42）

步骤固定：

1. 选择/粘贴单张图片。
2. 本地 OCR（默认）。
3. 编辑校对文本。
4. 可选翻译。

本地路径说明“图片留在此设备”；第一次模型下载显示可能较大且消耗设备 CPU/内存。取消必须停止 worker。

图片宽、高都必须大于 15 px，最长边不超过 4096 px，长边/短边小于 50；超过 4096 px 时本地等比缩小并展示调整后尺寸，过小或过于狭长时直接说明限制，不自动放大、裁切或补边。

云 OCR 是独立次要按钮“使用阿里云重新识别”：

- 只有点击后出现确认层，显示文件名、类型、调整后尺寸、大小、预计 1 次、剩余次数和接收方。
- 本地低置信度只提示，不自动弹确认、不自动上传。
- 云结果回到同一个可编辑校对区；不展示成已翻译。
- 点击“确认文字并继续翻译”后进入文本翻译工作台；目标语言默认中文，实际发送仍由用户点击“翻译”发起。

本地 OCR 路径不上传原图；只有上述明确选择云 OCR 的动作构成上传例外。

## 9. 阿里云设置 UX（Screen 41）

页面只对当前 owner 可见，不使用“角色/管理员权限”文案。

### 9.1 凭据

- AccessKey ID 与 Secret 首次都必填；保存后只显示 configured 状态和 ID 末 4 位。
- 替换凭据时两个字段重新填写；Secret 永不回显。
- 删除是独立危险动作，说明会禁用云翻译/OCR但不影响本地工具。
- 页面提供最小 RAM policy 复制区和控制台入口。
- 常驻说明“本地账本只统计本应用；阿里云免费额度按主账号与 RAM 子账号共享”。专用 RAM 只缩小权限，不能隔离同账号其他应用的用量；提供人工对账入口，不把本地剩余写成“阿里云官方剩余”。
- 保存本身不调用阿里云；状态写“尚未通过真实调用验证”，不能假装连接测试成功。
- Screen 41 中如出现“连接验证”的折叠视觉示意，不实现绕过额度的独立测试 API；V2 只用第一次用户确认的真实调用更新最近状态。

### 9.2 翻译

- 通用/专业硬上限分别输入，默认 950000、最大 1000000。
- 自动切专业版开关默认开。
- 开启时专业场景必选；六个官方值使用“商品标题 / 商品详情 / 买卖家沟通 / 医疗 / 社交 / 金融”与原始 code。不得把 `communication` 改名为工程记录或默认推荐；每个场景旁说明其专业语言方向有限。
- 当前月已用值与上限并排；不能保存小于 `used + reserved` 的新值。

### 9.3 OCR 和并发

- OCR 默认 190、最大 200；明确“超过应用上限前停止，阿里云服务本身可能自动后付费”。
- owner 并发默认 1，范围 1–3；全局默认 3，范围 1–10；全局小于 owner 时表单就地报错。
- 队列容量和超时是产品固定行为，不出现在设置页。

## 10. 状态矩阵

每个适用页面至少覆盖：

| 状态 | 必须表达 |
|---|---|
| 初始空 | 可做什么、输入限制、处理位置 |
| 输入中 | 计数、模式、未执行状态 |
| 本地处理中 | 延迟超过 300 ms 后进度和取消 |
| 本地成功 | 结果、复制、明确没有上传 |
| 本地错误 | 位置、原因、修正动作；保留输入 |
| 超限 | 实际值、允许值；不自动截断 |
| 云确认前 | 接收方、准确 payload 范围、预计额度 |
| 排队 | 位置、到期、取消 |
| 云运行 | 片段/步骤进度、实际引擎、取消语义 |
| 云成功 | 结果、实际计量、剩余、RequestId |
| 云明确失败 | 稳定原因、是否已计量、手动动作 |
| 结果不确定 | 保守计量、不自动重试、重复计费风险 |
| 额度不足 | 硬停止、重置月份、本地账本说明 |
| 凭据/场景缺失 | 精确设置入口，不清空当前输入 |
| 离线 | 本地工具仍可用；云操作禁用并说明 |

Screen 42 是这些状态的组件参考，不是产品路由或状态大屏。

## 11. 可访问性与键盘

- 延续一期 WCAG AA、可见焦点、44×44 px 手机触控目标和 `prefers-reduced-motion`。
- 所有控件有可见 label；placeholder 不是 label。
- 编辑器前后提供“跳到操作区/跳到错误列表”，避免键盘用户困在数千行文本。
- 错误摘要使用 `role=alert` 或适当 live region；连续进度只在有意义的阶段变化时播报，不能每个字符刷屏。
- 状态不只用红/绿；同时有图标、标题和文字。
- 复制成功是短 live message，不自动移动焦点。
- 对话框锁定焦点；关闭后回触发点；危险动作默认焦点不放在确认按钮。
- Monaco 和 CodeMirror 使用同一外层可访问文案与快捷键说明；不得只为桌面提供关键业务动作。

## 12. 文案词典

统一使用：

- “Base64 编码/解码”，不用“加密/解密”。
- “哈希摘要与校验和”，不用“文本摘要”。
- “浏览器本地处理”，不用模糊的“离线安全”。
- “阿里云机器翻译”“阿里云通用文字识别”，不用“AI 翻译”“智能 OCR”泛称。
- “本地保护账本剩余”，不用“阿里云官方余额”。
- “结果不确定”，不用“请求失败”掩盖可能已计费。
- “签名已验证”和“Claims 通过”分开，不使用一个“JWT 有效”。

## 13. 实现交接清单

页面 owner 开始编码前必须：

1. 读取 `09`、`10`、`11`、本文和对应 Screen ID。
2. 确认该工具属于当前发布里程碑；未发布就不注册路由。
3. 列出默认、空、输入、成功、错误、超限、取消和移动状态。
4. 标出本地/云端数据边界和唯一主操作。
5. 确认复用现有 token，不复制 Stitch HTML 或示例值。
6. 对编辑器/Worker 页面写出卸载与取消路径。
7. 用真实 390 px、1024 px 和宽桌面视口检查，不只看静态截图。

视觉验收不能只比像素：还要验证真实长文本、错误行列、键盘、焦点、排队、额度变化、结果不确定和浏览器刷新后的边界。
