# 设计交接与 Stitch 使用指南

状态：**已确认，受 `00-V1-BASELINE.md` 与 `05-UX-DESIGN-BASELINE.md` 约束**

本文把一期 Stitch 设计稿与开发里程碑建立稳定映射，使新的开发任务无需依赖聊天记录即可定位正确画面。设计稿负责视觉、布局和交互状态参考；产品范围、数据、安全、API 和验收语义仍以仓库权威文档为准。

## 1. 权威来源与项目定位

- Stitch 项目：[开发百宝箱](https://stitch.withgoogle.com/projects/10575442033726834971)
- Project ID：`10575442033726834971`
- 一期设计系统 Asset：`assets/b1bf5312e98e46b7840bce775be1882a`
- 设计系统：`开发百宝箱`，版本 `v3`，默认深色
- 页面范围：`01`–`33`，其中 `01`–`06` 是基础与响应式参考，`07`–`33` 对应 M1–M5

发生冲突时按以下顺序处理：

1. 用户当前明确要求与 `AGENTS.md`。
2. `00-V1-BASELINE.md` 及对应专题契约。
3. `05-UX-DESIGN-BASELINE.md`。
4. 本文中的画面映射与使用规则。
5. Stitch 画面中的示例数据和视觉细节。

不得因为 Stitch 示例中出现了字段、状态、快捷键或操作，就绕过基线把它实现为新产品能力。发现冲突时先更新权威文档和设计稿，再实施代码。

## 2. 在新任务中读取设计稿

具备 Stitch MCP 时，按以下顺序读取：

1. 使用 Project ID 调用 `list_screens`，确认项目可访问。
2. 根据第 4 节表格找到当前里程碑的规范 Screen ID。
3. 使用 `get_screen` 读取该 Screen ID 的截图和 HTML 上下文。
4. 需要设计令牌时读取上面的设计系统 Asset；不要改用项目中的旧版设计系统或 Stitch 默认主题。

规范资源名格式：

```text
projects/10575442033726834971/screens/{screen_id}
```

部分派生修订版可能不会立即出现在 `list_screens` 的默认列表中，但仍可按表中的 Screen ID 直接通过 `get_screen` 读取。不要因为列表暂时只显示原稿，就退回使用同编号的旧版本。

没有 Stitch MCP 时，可以先根据本文、`05-UX-DESIGN-BASELINE.md` 和验收文档实施非视觉骨架；涉及布局、组件外观或响应式定稿前，必须恢复 Stitch 访问或由用户提供对应编号的导出图，不能凭空重建另一套视觉语言。

## 3. 开发使用原则

- 表中的 Screen ID 是同编号的规范版本。同编号存在原稿、本地化修订、定点文案修订或深色修订时，只使用表中版本。
- Stitch 的截图和 HTML 是设计参考，不是生产代码。不得整页复制生成 HTML、内联样式或临时图标；应使用 Vue 组件、项目设计令牌和明确的响应式布局实现。
- `01 组件与令牌板` 是设计系统参考，不是产品路由。
- 标题包含“状态板”“三状态板”的画面把同构状态并排展示以便开发验收，不代表要在产品中创建一个状态板页面。应把这些状态实现为同一真实页面或组件的 loading、empty、error、offline、disabled、cancelled 等变体。
- 示例记录、命令、Provider 名称、Token 名称、日期和统计值只是展示数据，不能当作固定业务数据写入代码。
- 默认使用简体中文；只有代码、命令、路径、文件名、协议、模型名及必要技术专有名词保留英文。
- 搜索和快速记录必须有可见入口。最终快捷键尚需按里程碑完成浏览器 smoke 后回填，不能从旧图或示例中恢复 `Cmd/Ctrl+K`、`Cmd/Ctrl+Shift+N` 等未确认组合。
- 原始记录、补充原始记录和附件属于只读事实层；AI 内容必须标明来源、版本、生成时间、尚未验证与 stale/invalidated 状态。
- 敏感正文和密钥默认遮挡；揭示、复制、发送外部 AI、永久删除和其他高风险动作必须遵循仓库安全契约。
- 普通纯文本只提供整体展示和“复制全部原文”；只有 Markdown fenced code 与受控 AI command/code block 使用逐块复制组件。
- 足够宽的桌面采用三栏工作台；约 1024 宽度先收起模块导航，不持续压缩命令正文；390 手机端使用单栏、可预测返回和可见主操作。

## 6. 实现与验收工作流

每个页面或功能按以下最小闭环实施：

1. 先读 `AGENTS.md`、`00-V1-BASELINE.md`、对应专题契约和本里程碑验收项。
2. 获取表中的规范画面；同时查看 `01` 的令牌与适用的桌面/移动母版。
3. 识别可复用的应用壳、导航、列表、详情、状态提示、确认层和代码块组件，不按截图逐页复制。
4. 实现真实数据和状态转换，避免把截图示例值或状态板布局硬编码进产品。
5. 至少验证默认、加载、空、错误、禁用、焦点、溢出和适用的敏感/离线/取消状态。
6. 对照 `05-UX-DESIGN-BASELINE.md` 和 `06-DELIVERY-AND-ACCEPTANCE.md` 验证键盘、响应式、可访问性和产品边界；静态截图相似不等于交互完成。

```text
Stitch 只作为视觉与交互状态参考，产品、数据、安全和 API 语义以仓库权威文档为准。
```
