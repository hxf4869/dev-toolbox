# 一期 UX 与视觉基线

状态：一期冻结候选

设计方向：Stitch 项目 [10575442033726834971](https://stitch.withgoogle.com/projects/10575442033726834971)

主要场景：桌面浏览器中的快速记录、搜索、核对与复制

## 1. 设计目标

开发百宝箱一期追求“安静、紧凑、可靠的工程工具”，不追求营销感或视觉炫技。界面首先帮助用户完成四件事：

1. 几秒内把剪贴板内容保存为原始记录。
2. 把搜索当成主要入口，而不是在复杂目录中浏览。
3. 一眼区分原始事实、人工元数据和 AI 派生内容。
4. 在复制命令前看到来源、时间、敏感状态与模型风险提示。

视觉品质的判定不是“元素很多”或“像大厂产品”，而是：对齐稳定、层级明确、状态齐全、键盘顺畅、深浅主题一致、长内容不破版。

## 2. 已确认方向与需要修正的点

### 2.1 保留的 Stitch 方向

- 深色为默认主题，灰黑中性色面板配克制蓝色强调色。
- 左侧全局工具栏 + 模块导航 + 记录列表 + 详情区的桌面工作台结构。
- 目录树、搜索结果和详情同时可见，减少来回跳转。
- 卡片边界轻、阴影少，以信息密度和排版建立层级。
- 代码/命令使用独立等宽区域。
- 浅色、深色切换入口放在全局壳层，而非某个业务页面。

### 2.2 实现前必须修正

- 详情页不能只显示 AI 整理结果；必须持续提供“原始记录 · 只读”入口和来源信息。
- “AI Task Completed”一类成功文案只能表示生成任务完成，不能让绿色状态暗示命令已验证安全。
- 每个独立命令块都有自己的复制按钮，不只在整个详情底部放一个“复制”。
- 搜索必须比目录更突出，首屏显示排序方式、过滤状态和结果命中片段。
- 导航中的“固定视图、目录、标签、未来工具”使用不同层级和图标语义，不能混成一个树。
- 界面主文案统一简体中文；命令、协议和技术名词可以保留英文。

完整视觉审查保存在 [`references/STITCH-CRITIQUE.md`](./references/STITCH-CRITIQUE.md)。该审查是设计输入，不是产品指令；本文件才是实现约束。

## 3. 信息架构

### 3.1 全局应用壳

最左侧全局工具栏服务于“未来会有多个小工具”的长期方向，但一期只出现真实功能：

```text
全局工具栏
├── 开发百宝箱标识 / 展开
├── 工作台（知识与记录）
├── 任务（AI 任务列表）
├── 设置
├── 帮助
└── 账号 / 退出
```

- 不显示空的“更多工具”“插件市场”或不可点击图标。
- 未来工具通过新增明确图标和路由进入；一期不实现动态插件导航。
- 全局工具栏收起时仍为图标提供 tooltip 和可访问名称。

### 3.2 工作台模块导航

工作台导航按固定语义分组：

```text
固定视图
├── 收件箱
├── 最近
├── 收藏
├── 敏感
├── 图片
└── 文件

目录
└── 用户目录树

标签
└── 高频标签与“查看全部”
```

- 固定视图用导航图标；目录只用文件夹图标；标签用标签图标。
- 当前项使用强调色文字、同色低透明背景和左侧/轮廓状态中的一种，不叠加多种强提示。
- 数量只在能帮助判断待处理状态时显示，例如收件箱数量；不为所有项堆徽标。

### 3.3 工作台主区域

桌面宽屏顺序固定为：

```text
[全局工具栏] [模块导航] [搜索与结果列表] [详情]
```

详情页签固定为：

1. `AI 整理`
2. `原始记录 · 只读`
3. `附件`
4. `历史`

AI 整理页内部结构由受控 block JSON 动态生成；页面外壳、来源栏、任务状态和安全提示不能由模型决定。

## 4. 布局与响应式规则

### 4.1 桌面宽屏（≥ 1280 CSS px）

| 区域 | 默认宽度 | 可调整 | 最小/最大 |
|---|---:|---|---|
| 全局工具栏 | 56 px | 否 | 固定 |
| 模块导航 | 236 px | 可折叠 | 216–280 px |
| 搜索结果 | 392 px | 是 | 340–480 px |
| 详情 | 剩余空间 | 否 | 最小 520 px |

- 分栏之间只使用 1 px 分隔线；拖动结果列表宽度时显示清晰手柄和光标。
- 用户调整后的结果列表宽度可保存在本机偏好中；不进入服务端业务数据。
- 详情标题、页签和来源栏吸顶；详情正文独立滚动，避免整个页面滚动导致上下文丢失。
- 导航与结果列表各自滚动，不允许四列共同横向滚动。

### 4.2 中等宽度（960–1279 px）

- 全局工具栏保留。
- 模块导航默认收起为抽屉，结果列表保持 340–380 px。
- 选择记录后详情与列表并排；详情最小 520 px。
- 搜索和“快速记录”始终可达，不能被收入多层菜单。

### 4.3 窄桌面/平板（600–959 px）

- 使用列表页 → 详情页的两级路由，不强压三栏。
- 返回按钮恢复原搜索词、过滤器、排序和列表滚动位置。
- 目录与过滤器使用侧边抽屉；抽屉关闭后焦点回到触发按钮。

### 4.4 手机（< 600 px）

- 一期只保证登录、搜索、阅读、附件下载和单块复制。
- 不承诺高效批量录入、目录拖动、并排对比或三栏。
- 底部不新增原生 App 式导航；沿用简化的 Web 顶栏和页面路由。
- 内容不能产生页面级横向滚动；代码块内部可以横向滚动。

### 4.5 缩放与内容压力

- 200% 浏览器缩放时，主要流程仍可操作且不遮挡确认按钮。
- 测试至少覆盖 1366×768、1440×900、1920×1080、1024×768 和 390×844。
- 测试超长标题、10,000 字记录、500 字符单行命令、30 个标签、中文/英文/路径混排和 20 MiB 文件。
- 文本截断必须可通过 title/tooltip、展开或详情看到完整值；不可静默永久丢失。

## 5. 设计令牌

所有页面只使用语义令牌。禁止在业务组件里直接写新的品牌色、间距、圆角或阴影值；新增令牌先在 `apps/web/src/design/` 中说明消费者。

### 5.1 颜色

初始令牌如下，正式实现可在不改变语义和对比关系的前提下微调一次，之后冻结：

| 语义令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg-app` | `#151716` | `#F4F6F5` | 应用最底层 |
| `--bg-nav` | `#191B1A` | `#ECEFEE` | 导航区域 |
| `--bg-surface` | `#1F2220` | `#FFFFFF` | 列表/详情表面 |
| `--bg-elevated` | `#272A28` | `#F7F9F8` | 弹层、悬浮、输入 |
| `--bg-code` | `#171918` | `#F1F3F2` | 代码与命令块 |
| `--border-subtle` | `#343835` | `#D9DEDB` | 普通分隔线 |
| `--border-strong` | `#4A504C` | `#B8C0BB` | 聚焦前的强边界 |
| `--text-primary` | `#F1F4F2` | `#1B201D` | 主文字 |
| `--text-secondary` | `#B5BBB7` | `#4E5751` | 次级文字 |
| `--text-muted` | `#8A928D` | `#69736D` | 时间、占位、辅助 |
| `--accent` | `#6E9BFF` | `#2E65D5` | 选中、链接、主操作 |
| `--accent-soft` | `#243557` | `#E7EEFF` | 选中背景 |
| `--success` | `#58B879` | `#247A43` | 系统任务成功，不代表命令正确 |
| `--warning` | `#E0A34A` | `#9A5B00` | 风险与需核对 |
| `--danger` | `#E36B63` | `#B42318` | 删除、失败、敏感危险 |
| `--sensitive` | `#F07A45` | `#B54708` | 敏感标签，区别于系统错误 |
| `--focus-ring` | `#8DB0FF` | `#245FD1` | 键盘焦点 |

规则：

- 主操作每个视图最多一个实心强调按钮。
- 绿色只说明系统动作完成，例如“保存成功”“生成完成”；不得写“已验证安全”。
- 警告用琥珀色并带图标/文字，不能仅靠颜色。
- 敏感标签和删除动作不共用同一文案语义，即使颜色接近。
- 大面积表面不使用纯黑、纯白、渐变或透明玻璃效果。
- 正文与背景至少满足 WCAG AA；最终实现需自动检查常用令牌组合。

### 5.2 字体

```css
--font-ui: Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", Menlo, Monaco, Consolas,
  "Liberation Mono", monospace;
```

- 不从第三方 CDN 加载字体；使用系统字体或随应用打包的字体。
- 正文默认 14 px / 1.55；列表摘要 13 px / 1.45；辅助信息 12 px / 1.4。
- 页面标题 20 px / 1.3、600；区块标题 16 px / 1.4、600；卡片标题 15 px / 1.4、600。
- 命令和代码 13 px / 1.55；不得为了塞入更多字符降到 12 px 以下。
- 中文正文不使用全大写或过大字距；英文小标签可以使用轻微字距但不超过 `0.04em`。

### 5.3 间距与尺寸

只使用以下基础间距：`4, 8, 12, 16, 20, 24, 32, 40 px`。

| 场景 | 值 |
|---|---:|
| 紧密图标与文字 | 8 px |
| 表单标签与控件 | 8 px |
| 同组控件 | 12 px |
| 卡片内边距 | 14–16 px |
| 区块间距 | 24 px |
| 页面水平内边距 | 16–24 px |
| 主要可点击高度 | 40 px |
| 图标按钮 | 40×40 px |
| 紧凑列表行 | 最小 44 px |

- 关键触控动作在移动端增至至少 44×44 CSS px。
- 表单不得仅靠 placeholder 充当标签。
- 同一层级列表的标题、摘要、标签和时间使用统一基线与间距。

### 5.4 圆角、边界与阴影

- 输入、按钮、标签：6 px。
- 卡片、代码块、下拉菜单：8 px。
- 对话框和大抽屉：12 px。
- 胶囊只用于状态/标签，不用于普通按钮和卡片。
- 普通层级使用边框区分；只有菜单、对话框和拖拽层使用单一轻阴影。
- 不使用多层阴影、发光、3D 浮雕或大面积模糊。

### 5.5 动效

- 主题切换、抽屉、菜单和复制反馈使用 120–180 ms。
- 页面主区域不做入场动画；列表搜索结果不逐项飞入。
- 加载超过 300 ms 才显示骨架或进度，避免闪烁。
- 遵循 `prefers-reduced-motion`，关闭非必要位移与过渡。
- AI 运行状态可以使用低频进度指示，不使用持续旋转的大面积装饰。

## 6. 核心页面规范

### 6.1 登录

- 单列、窄卡片，显示产品名、用户名、密码和登录按钮。
- 密码正确但需 TOTP 后切换到第二步；不在同一屏同时堆全部字段。
- TOTP 步骤提供 6 位输入、恢复码入口和“信任此设备 90 天”开关。
- 错误统一显示在表单顶部并关联到字段，不泄露具体凭据错误。
- 登录页不展示注册链接、社交登录、忘记密码邮件或营销插图。

### 6.2 快速记录

- 全局快捷键 `Cmd/Ctrl + Shift + N` 打开快速记录层。
- 打开后焦点直接进入正文；支持粘贴纯文本、Markdown、图片和附件。
- 首屏必填控件只有正文/附件与“是否包含敏感数据”。敏感项使用明确二选一，不藏在高级设置。
- 标题、目录、标签和来源说明在“更多选项”中，默认不阻碍保存。
- `Cmd/Ctrl + Enter` 保存；`Esc` 关闭前，如果有未保存内容必须确认。
- 保存成功立即清空或按用户选择继续编辑；AI 整理不能阻塞保存反馈。
- 上传展示每个附件名称、大小、状态和移除动作；单文件超限在选择后尽早提示，服务端仍二次校验。

### 6.3 搜索与列表

- `Cmd/Ctrl + K` 聚焦全局搜索；搜索框持续显示在结果列表顶部。
- 输入 150–250 ms 后发起查询；新请求取消旧请求，不要求按 Enter。
- 查询词、过滤器、排序写入 URL，使刷新和前进/后退可恢复。
- 排序显式提供“相关性 / 时间”，不使用难以发现的图标切换。
- 活动过滤器显示可单独清除的 chips，并提供“清除全部”。
- 结果卡片固定顺序：标题 → 命中片段 → 标签/类型 → 来源与时间；敏感结果只显示遮挡片段。
- 敏感/未知记录可以显示用户明确设置的标题、目录、标签和时间；未填标题时只能显示安全通用标题，不能把原文首行或 AI 摘要当标题。
- 选中结果使用边框/背景强调，不能靠文字变蓝这一个信号。
- 列表首载用骨架；继续加载用底部状态；不使用无限滚动吞掉定位，采用游标分页和显式“加载更多”或自动触发但保留位置。

搜索状态必须齐全：

- 初始：最近或当前固定视图，不显示“请输入关键词”的空洞页面。
- 加载：保留输入和旧结果的可辨识状态，避免整栏跳空。
- 无结果：回显查询与过滤，提供清除过滤和新建记录。
- 错误：保留查询，提供重试，不伪装成无结果。
- 离线/API 不可用：明确说明录入和搜索暂不可用，不显示陈旧数据为最新。

### 6.4 详情与来源

详情顶部固定展示：

- 标题和收藏动作。
- 目录、标签、敏感状态。
- 来源类型/路径、有效采集时间、原始记录短 ID。
- AI 视图时额外显示 `AI 整理 · 未验证`、模型、版本、生成时间和引用原始记录数量。

原始记录：

- 明确标记“只读事实层”。
- 正文不可直接编辑；人工标题、目录、标签和备注从独立编辑动作修改。
- 提供“从此原文重新生成”但不覆盖任何旧 artifact。

AI 整理：

- 没有 artifact 时显示任务用途、费用提示和“开始整理”。
- 运行中显示阶段与取消；不伪造逐字思考过程。
- 失败保留原文可用性，显示稳定错误和重试。
- 成功后显示“模型生成，执行前核对原文”，而不是“已验证”。
- 有原文依据的 warning 引用对应片段并可点击定位；仅来自模型知识的 warning 必须显示“无原文依据，需外部核对”。

### 6.5 命令与代码块

每个 `command`、`command_steps` 或 `code` block 使用统一组件：

```text
[语言/步骤名] [来源：原文 / AI 整理]        [折行] [复制]
-------------------------------------------------------
命令正文（等宽）
-------------------------------------------------------
[可选风险或说明]
```

- 复制只复制正文，不包含提示符、行号、注释标签或风险文案，除非它们本来就是原始内容。
- 复制成功按钮短时变为“已复制”，同时向屏幕阅读器播报；失败给出可重试错误。
- 多步骤命令默认逐步复制；可以额外提供“复制全部”，但必须保留换行和顺序。
- 原文命令标记“来自原始记录”，AI 生成命令标记“AI 整理”。
- AI 命令存在设备名、路径、删除、格式化等风险时在块下显示琥珀提示；颜色之外配图标与文字。
- 长行默认不折行并提供横向滚动；用户可以切换折行。任何模式都不能截断复制内容。

### 6.6 图片与附件

- 图片列表使用一致比例的缩略图网格，点击进入详情；原图下载始终可用。
- 图片 AI 说明作为派生内容展示，明确模型和版本；未分析图片仍显示文件名、尺寸和采集时间。
- 普通文件使用列表：文件名、大小、类型、上传时间、所属记录和下载动作。
- 文件正文无预览、无内容搜索时明确说明，不显示无效的搜索/分析按钮。
- 20 MiB 是上传上限，不是视觉提示中的建议大小；超过时显示实际大小和上限。

### 6.7 AI 任务与设置

任务列表区分：待运行、运行中、模型审阅完成、失败、已取消。列表显示任务类型、对象、模型、开始/结束时间和费用/token（Provider 返回时）。

Provider 设置沿用用户参考的“提供方列表 + 编辑表单”模式，但一期只包含真实配置：

- 提供方 ID、名称、Base URL、协议、API Key、启用状态。
- 模型 ID、显示名、上下文、最大输出、工具调用能力、视觉能力。
- 协议只列 `OpenAI Chat Completions`、`OpenAI Responses`、`Anthropic Messages`。
- API Key 只可替换，不能显示明文；连接测试说明会产生一次外部请求。
- 自定义提供方是配置，不允许上传插件、脚本或任意适配代码。

危险设置（重置 TOTP、撤销全部设备、永久删除、允许敏感原文发送外部 AI）使用独立危险区，要求说明影响和明确确认，但不要求用户重复输入无关文字。

## 7. 动态 AI block 渲染

### 7.1 模型可以决定的内容

- block 的受支持类型、顺序、标题和正文。
- 标题、摘要、分类和标签建议。
- 命令步骤、表格、清单、提示、图片说明和附件引用。
- warning 的文本、严重度、依据类型与来源片段引用。

### 7.2 模型不能决定的内容

- Vue 组件名、HTML、CSS、JavaScript、iframe 或任意脚本。
- 页面布局、导航、主题颜色、按钮级别和系统确认流程。
- 是否隐藏来源、敏感标记或“模型未验证”提示。
- 执行命令、自动打开 URL、自动下载附件或写剪贴板。
- 任意外部资源地址或未授权附件 ID。

### 7.3 渲染规则

- 每个 Schema block type 只有一个项目组件实现；不能在不同页面复制样式版本。
- 未知 block 显示兼容占位：“此内容由较新版本生成，当前客户端暂不支持”，并允许查看原始 JSON 的脱敏诊断摘要；页面不崩溃。
- block 引用的片段/附件先由 API 验证归属，再由前端渲染。
- Markdown block 禁用原始 HTML；表格限制列数并在自身容器横向滚动。
- `callout` 严重度映射到固定语义色，模型不能传颜色值。
- artifact 过长时按区块渐进渲染或虚拟化需要基于实测；一期不预先引入通用画布或复杂布局引擎。

## 8. 基础组件约束

一期只建立真实会复用的组件：

- Button、IconButton、Input、Textarea、Select、Checkbox/Switch。
- Dialog、Drawer、Dropdown、Tooltip、Tabs、Toast。
- FormField、InlineError、EmptyState、Skeleton、StatusBadge。
- AppRail、ModuleNav、SearchBar、ResultCard、DetailHeader。
- CodeBlock、CommandSteps、MarkdownBlock、Callout、DataTable、AttachmentRow。

规则：

- 基础交互组件必须支持键盘、焦点管理和可访问名称；优先使用原生语义，复杂弹层可以选一个 Vue headless primitive 库，不能混用多个组件体系。
- 图标只使用一个统一的线性图标集合，通过项目 `Icon` 包装层调用；禁止页面内混入 emoji、不同粗细图标或从截图抠图。
- 不引入重量级后台管理主题，也不让第三方组件默认样式绕过设计令牌。
- 不预建图表、日历、看板、富文本编辑器、拖拽画布或未来工具组件。
- 组件变体只为当前消费者增加，不建立组合爆炸的“万能组件”。

## 9. 交互与键盘

一期全局快捷键：

| 快捷键 | 行为 |
|---|---|
| `Cmd/Ctrl + K` | 聚焦搜索 |
| `Cmd/Ctrl + Shift + N` | 打开快速记录 |
| `Cmd/Ctrl + Enter` | 保存当前记录/提交明确表单 |
| `Esc` | 关闭最上层弹层或取消当前临时操作 |
| `↑` / `↓` | 焦点在结果列表时移动选中项 |
| `Enter` | 打开当前选中结果 |

- 快捷键不能覆盖浏览器常用行为；输入框内的方向键保持编辑语义。
- `Cmd/Ctrl + K` 的提示显示在搜索框中，但不能代替可访问标签。
- 所有操作都必须有鼠标入口，快捷键不是唯一入口。
- 焦点环始终可见；不因鼠标样式需求全局移除 outline。
- 弹层关闭后焦点返回触发器；路由进入详情后将焦点合理移至详情标题且不打断屏幕阅读器。

## 10. 文案与状态语义

### 10.1 固定术语

| 使用 | 不使用 |
|---|---|
| 原始记录、原文 | 源文件（除真实文件外） |
| AI 整理 | AI 优化原文 |
| 模型审阅完成 | 验证通过、安全可用 |
| 重新生成 | 覆盖、修正原文 |
| 敏感记录 | 密码条目（因为格式不固定） |
| 相关性搜索 | 语义搜索（一期没有 embedding） |
| 可信设备 | 永久登录、免密设备 |

### 10.2 操作反馈

- 成功：说明完成了什么，例如“原始记录已保存”“已复制命令”。
- 错误：说明未完成什么、数据是否保留、用户下一步是什么。
- 警告：说明风险和核对对象，不使用模糊“请注意”。
- 等待：说明正在保存、上传还是调用模型；AI 不能只显示无上下文 spinner。
- 删除：区分“移入回收站”和“永久删除”。永久删除明确列出原文、附件和 AI 版本都会移除。

## 11. 可访问性

- 目标 WCAG 2.2 AA；不追求形式化认证，但关键路径必须通过自动和人工检查。
- 所有输入有可见 label，错误通过 `aria-describedby` 关联。
- 图标按钮有可访问名称；纯装饰图标对辅助技术隐藏。
- Tabs、Dialog、Menu、Tree 按相应 ARIA 交互模式实现，不用普通 `div` 模拟后遗漏键盘。
- 状态不只依赖颜色；选中、敏感、错误、成功都有文字或图标。
- DOM 顺序与视觉顺序一致；三栏不能通过 CSS 排序制造屏幕阅读器跳跃。
- Toast 只用于短反馈，重要错误同时保留在页面中。
- 代码块允许键盘进入滚动区，复制按钮不遮挡正文。
- 深色和浅色主题、Windows 高对比/强制颜色模式至少完成基础可用检查。

## 12. Agent 开发约束

前端实现 Agent 必须遵守：

1. 先复用语义令牌和现有基础组件，再写业务页面。
2. 不根据单张截图用绝对定位复刻；必须满足本文响应式和内容压力规则。
3. 不在一个页面里发明新的色板、字体层级、圆角或按钮样式。
4. 不用 lorem ipsum 或全英文占位掩盖中文排版问题；使用脱敏但真实长度的工程内容。
5. 不把模型 JSON 直接映射为 HTML；只经过固定 block renderer。
6. 不为了“更现代”加入渐变、毛玻璃、发光、巨型标题、漂浮卡片或无意义动画。
7. 不实现文档未列出的入口；范围外想法写入 `BACKLOG.md`。
8. 每完成一个核心页面，同时完成加载、空、错误、禁用、溢出、键盘和深浅主题状态。
9. 视觉验收使用真实浏览器截图与交互，不以组件测试快照代替。
10. UI 调整不能改变原始/派生数据、安全或 API 语义。

## 13. 一期视觉验收

以下是发布门禁：

- [ ] 登录、快速记录、搜索列表、详情、图片/文件、任务和设置使用同一套令牌与组件。
- [ ] 深色与浅色都没有不可读、遗漏主题或浏览器默认控件突兀问题。
- [ ] 1366×768 下主要内容可用，详情命令区不被挤到不可读。
- [ ] 1024×768 正确收起模块导航；390×844 可完成登录、搜索、阅读和复制。
- [ ] `Cmd/Ctrl + K`、快速记录、保存、结果键盘导航和 Esc 均按规则工作。
- [ ] 原始记录始终可达且标记只读；AI 结果始终标记模型生成/未验证。
- [ ] 原文命令与 AI 命令视觉来源明确，每个命令块都可独立复制。
- [ ] 敏感内容在列表、DOM、复制和通知中遵循遮挡状态。
- [ ] 长命令、长标题、多标签、大图、任务失败和 Provider 未配置不破版。
- [ ] 200% 缩放、仅键盘、屏幕阅读器基本路径和 reduced motion 完成检查。
- [ ] 不存在空的未来工具、插件、语义搜索或 Notion 导入入口。
